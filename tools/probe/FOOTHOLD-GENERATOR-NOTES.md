# foothold 生成器 — 設計與依據

**狀態**：設計完成，程式碼未寫。
**依據**：`docs/MAP-STRUCTURE.md` §5.2（三條硬規則）、`tools/anatomy/sample-10.json`（實測基準）。

---

## 1. 為什麼不能沿用現有的 `/auto-foothold`

現有實作從**素材自帶的 Convex 幾何**推導 foothold。那是對的設計，
但實測證明真實 NX 素材沒有這個東西：

```
f1/Tile/ancientForest.img/bsc/0 的子節點：
  origin | Vector
  z      | Long
```

`/auto-foothold` 的拒絕行為是**正確的**——它回「寧可什麼都不做」，
那是這個工具一貫拒絕靜默發明的立場。**這不是要修的 bug，是要新增一種幾何來源。**

---

## 2. 生成原理

foothold 是「線段 + 鏈」。要讓角色站得住，需要的是**可走行的表面**，
不是裝飾。來源有兩種，優先順序如下：

### 來源 A：素材幾何（沿用 `/auto-foothold`）

有就用。這是最高保真——素材作者知道哪裡能站。

### 來源 B：由已鋪圖塊的**輪廓**推導（本輪新增）

一張圖塊在 `(x, y)`，尺寸 `w × h`，原點 `origin(ox, oy)`。
它在世界座標的矩形是：

```
左 = x - ox        右 = x - ox + w
上 = y - oy        下 = y - oy + h
```

推導規則（依 `sample-10.json` 的實測分佈校準）：

1. **取每一行的下緣**作為候選線段。逐行掃描輪廓，水平相鄰的圖塊
   合併成一段——這直接產生 `slope`（連續傾斜面），而實測顯示
   斜坡佔 142/156，是主流而不是階梯。
2. **相鄰列上下緣的落差**決定 `y`。落差為 0 → 平地；不為 0 → 斜坡。
   這是「連續傾斜面」與「階梯」的差別，必須保留，不能量化成階梯。
3. **鏈的連接**：一段的右端點與下一段的左端點在同一條鏈上時接起來。
   依規則二，`prev`/`next` 必須雙向且**零斷裂**——
   `WriteFootholdChains` 已經保證這點（`prev: id-1`、`next: id+1`、
   首尾為 0），所以生成器只需交出**連續的點序列**，鏈由 writer 建。

### 規則一：layer 跟著視覺圖層

**絕不寫死 layer。** foothold 的 layer 必須是它所承載的那一層。
東部岩山橫跨 L0–L3，深海峡谷全在 L4——上一任 agent 只抽一張地圖就以為
固定 layer 4，抽第二張才推翻。本生成器以「圖塊在哪一層，foothold 就在哪一層」
為不變量。

### 規則三：斜坡是主流

不做垂直牆（wall）的自動生成。實測牆面只佔 9–36%，
且牆代表重力方向選擇——那是**設計決定**，不是從輪廓推導出來的東西。
寧可少生成，不要生成錯誤的重力語意。

## 3. 拒絕生成的情況

| 情況 | 理由 |
|---|---|
| 圖層沒有任何圖塊 | 沒有輪廓就沒有表面 |
| 單張圖塊孤立放置 | 鏈會是 2 點 1 段，角色走不到第二個圖塊；寧可明確拒絕 |
| 圖塊的 `origin` 缺失 | 算不出世界座標，猜 origin 會整張地圖偏移 |

**寧可什麼都不做，也不要猜。** 這是這個工具的既有立場。

---

## 4. 驗收

```
鋪一片地面 → 自動產生 foothold → /validate 回報 brokenChains=0
→ 存檔 → 冷啟動重讀 → /validate 仍為 0
```

外加兩條比對 `sample-10.json` 的合理性檢查：

- 產生的鏈**雙向零斷裂**（`brokenChains=0`）
- 產生的線段斜率分佈接近實測（斜坡為主，不是階梯）

## 5. 待確認（實作時要驗）

1. `origin` 的語意：是圖塊內部的錨點還是左上角？
   `sample-10.json` 的 `tileYs` 欄位可能有線索，實作前要讀。
2. 鏈的接續規則：相鄰列之間，上一列的右端與下一列的左端
   未必等於 x。實作時要先在真實地圖上量出來再寫死。
3. `group` 的分段語意：實測 group 0 是主地面，其餘是不同區塊。
   自動生成的鏈是否都該放 group 0，要用真實地圖比對。
