## 三條真實的阻斷

### B1 — 記憶體決定了能開什麼檔案

實測：Map.nx 678 MB 需要 **13.4 GB** 展開；Mob.nx 817 MB 需要約 **16 GB**。
四個殘留伺服器吃掉 18.5 GB，導致第五個開檔失敗並報成「檔案損毀」。

**現在可用 20.8 GB，夠開 Mob.nx — 但只夠一個實例。**

規則：任何時刻只留一個伺服器。需要地圖 + 怪物時，開 Map.nx + Mob.nx
在同一個實例裡，不要分開。

### B2 — 容器結構我不能靠 `/api/children` 猜

`000030000.img` 頂層有 `foothold` 節點，而 `foothold/1/11` 下又是數字節點；
`/api/children` 回傳的內容與 `BuildFootholds` 實際解析的三層結構
（`foothold/<layer>/<group>/<foothold>`）不一致。我繞了 20 分鐘才搞對。

規則：**先讀解析程式碼（`MapDocument.cs:342`）再查 API**，不要用 API 結果
反推結構。

### B3 — 驗收工具本身會壞

今天有四次「程式對、工具錯」：選擇器 id vs class、CDP 截圖回傳黑畫面、
掃描器門檻對不實作常數（三次）、背景程序互相覆寫 checkpoint。

規則：**每個驗收工具的判準必須引用實作的常數名稱**，例如
`y > bounds.bottom + FallOutSlack(60)`，不能自己另外訂一個數字。

## 執行順序

### 階段 1 — 怪物（唯一的視覺大缺口）

地圖是空的，怪物讓地圖活起來。Mob.nx 817 MB 一個像素還沒畫。

1. 在**同一個**伺服器開 Map.nx + Mob.nx（記憶體規矩）。
2. `GET /api/simulate/mob-sprite?path=f1/Mob/1000000.img&action=stand1&frame=0`
   確認能回傳 canvas。
3. `GET /api/simulate/session` 的 `mobs[]` 從空變成有內容，且每個有
   `x/y/z/art`。
4. **驗證**：選一張有怪物的地圖，抓 canvas 的 `toDataURL()`，
   視覺確認怪物畫在正確的 Z 層、位置對、動作會變。

**不做**：怪物 AI、掉落物、技能。參考專案有，但先讓它出現。

### 階段 2 — NPC / life

`life/0` 已有完整資料（`cy/f/fh/id/type`），只差畫。

1. 新端點 `GET /api/simulate/npcs?path=...`。
2. 從 `life` 節點解析 id/type，回報座標與 art 路徑。
3. **驗證**：抓 canvas，確認 NPC 靜態站在 foothold 上、圖對。

### 階段 3 — 攝影機實測（我宣稱過但沒量完）

`bounds` 現在有了，夾限有了，但我沒有獨立量過「角色在畫面上的位置」。

1. 靜止時角色在 viewport 的位置比例。
2. 按住方向鍵 3 秒後再量一次。
3. 兩張不同縮放的截圖，角色必須都在中央。
4. **驗證**：數字 + 兩張截圖。缺一不可。

### 階段 4 — 全螢幕的回歸保護

第二十發改了 959 行 `walkview.js`。我驗過沒破壞，但那是**當時**。
每個階段結束都重跑一次 `verify-fullscreen.mjs`。
