# 2026-10-14 13:26 — 人物左右走動時素材方向相反

## 問題（使用者直接指出）

「現在人物 左右 走動 人物素材方向是相反的」
—— 走動正常，但人物素材朝向與行走方向相反。

## 遇到的第一個問題：我去分析圖片，而不是讀程式碼

使用者直接糾正：「你為什麼他媽的要分析圖片阿 你明明是代碼有問題 分析讀片幹嘛啊?」
我當時用 vision_analyze 判斷小圖的朝向，還得到錯誤結論。
**問題已經被說清楚了，工具應該是 grep 和讀碼，不是看圖。**

## 根因

`wwwroot/js/avatar.js` `placement()`：

```js
flip: dir < 0,      // 錯
flip: dir > 0,      // 對
```

對標鏈（`C:\MUWORK\GAME\_necrocer_src\MapleNecrocer\Client\MapleCharacter.cs`）：

- `:1649-1652` 按右鍵設 `FlipX = true` → **FlipX=true 就是面對右**
- `:1340-1353`
  - `case true:  this.Flip = -1;`  面對右 → **鏡像**
  - `case false: this.Flip =  1;`  面對左 → **原圖不翻**

所以檔案裡的素材預設朝左，朝右要用鏡像。原碼 `dir < 0` 把它寫反了：
向右走不翻轉（顯示朝左的臉）、向左走翻轉（顯示朝右的臉）。

**與 13:00 那條攻擊框 `facingLeft ? Mirror : Box` 是同一個錯誤**：
同一個符號判斷寫反，同一個作者，同一個專案。

## 怎麼修的

1. `avatar.js` 兩處 `flip: dir < 0` → `dir > 0`
   （`placement()` 的早退分支與正常分支各一處）
2. 在程式碼註錄完整推導鏈，避免下次又被「看起來明顯」的寫法蓋掉
3. 部署到 `bin/Release/net10.0-windows/wwwroot/js/avatar.js`
   （伺服器服務的是 bin 不是原始樹），md5 比對一致

## 驗證（全部用數字，沒有用看圖）

| 測試 | 結果 |
|---|---|
| 伺服器供應的 avatar.js 是新版 | `flip: dir > 0` ✓ |
| 兩個朝向互為鏡像 | 1968 像素比對，**0 個不對稱** |
| 素材基準朝向 | 頭髮原圖墨色右側 227 / 左側 90 → 臉在左，**原圖朝左** |
| facing=-1（左走） | 頭髮左 201 / 右 116 → 臉在左 ✓ |
| facing=+1（右走） | 頭髮右 227 / 左 90 → 臉在右 ✓ |

**方法**：`f2/Hair/00030000.img/stand1/0/hair` 單層渲染，
頭髮蓋住後腦、留出臉，所以墨色較少的那一側就是臉的方向。
這是數值測量，不是看圖。

## 順帶確認（不是缺陷）

- `frame` DTO 沒有 `dir` 欄位，所以 `cur.dir ?? (cur.facing >= 0 ? 1 : -1)` 走的是 `facing`
- 實測：右走 `facing=1`、左走 `facing=-1`，伺服器端正確
