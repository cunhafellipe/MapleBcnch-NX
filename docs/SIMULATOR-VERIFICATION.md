# 模擬器嚴苛核驗程序

**建立**：2026-10-21。使用者指示「針對模擬器系統的所有功能下達嚴苛的核驗步驟」。
**權威規格**：`pm/SPEC.yaml`、`pm/decisions/ADR-0005`（四條驗收準則）、ADR-0006（固定傷害）、
ADR-0007（引用稽核）。**本文件不取代那些規格，它規定「怎麼驗」。**

---

## 0. 三條不可協商的規則

### 0.1 每一條發現必須通過 ADR-0005 的判準

> **「它會不會讓測試者看錯結果？會，就修；不會，放著。」**

沒通過這條的，不是缺陷，是範圍外。**照樣列出來，但要標明「不修 + 理由」**，
不要混進缺陷清單 —— 那會污染後續的優先序判斷。

### 0.2 引用不是證據，是待查的東西

ADR-0007 記錄的失敗模式**不是 bug**，是「引用了 `PARITY.md` 已排除的來源，
然後修補後果而不是檢查前提」。它留下的指示很明確：

> 「這個 codebase 裡任何一處引用 `Skill.cs`，其餘的姊妹引用都該被視為可疑。」

**因此：任何 C++ 引用必須開啟原始檔案、讀那一行、貼出原文。** 轉述不行，
「我相信是對的」不行，已經寫在程式碼裡也不行。

### 0.3 版本污染要單獨查

`clean-client` 是 v83 客戶端，但**它自己帶著 v95 的註解**。已知實例：

```
CharStats.cpp:54-56
  // v95 CSkillInfo::GetShootSkillRange (0x709650) gives bow/crossbow shoot
  // attacks a base reach of 300 and adds skill 3000002's range bonus
  // (远程箭, +15 per level). Other weapons keep the previous 250 fallback.
  projectilerange = Weapon::is_bow_or_crossbow(weapontype) ? 300 : 250;
```

**這個 `300` 來自 v95，`250` 才是被保留下來的值。** ADR-0007 把 `300 : 250`
當成 v83 參照引用了。凡是引用行的鄰近註解提到 v9x / v145 / 反編譯 / IDA 位址的，
**那個數字就要獨立判定它是哪一版的**。

## 1. 核驗的四個層次

由外到內。**前一層不過，後面不用做。**

### L1 — 引用稽核（最高優先）

掃描模擬器相關程式碼裡的每一個 C++ 引用（`Xxx.cpp:123`、`Xxx.h:45-60`）：

1. 開啟 `clean-client` 裡那個檔案，讀那一行。
2. 貼出**原文**。
3. 比對引用說的是不是那一行在講的事。
4. 若行的鄰近註解提到其他版本（見 0.3），標為 **版本待判定**，不要直接採信。

**產出**：引用稽核表（引用 / 實際原文 / 相符與否 / 備註）。

**特別注意**：`MapSimSessionStore.cs:9-15` 自己寫著它的引用指向 MapleNecrocer
且「未經重新稽核內容」。那一段裡的每一條引用都必須重查。

### L2 — 四條準則的覆蓋狀態

ADR-0005 的驗收只有四條。**每一條要回答：現在有沒有東西在驗它？驗的是什麼？**

| 準則 | 要問的問題 |
|---|---|
| 1. 位置準確 | 畫在哪裡是怎麼算出來的？這個算式有沒有對照參照原始碼？ |
| 2. 機制準確 | 按鍵 → 姿勢 → 傷害 → 特效，每一環有沒有斷？ |
| 3. 有即時效果 | 播放速率是從封存來的還 是寫死的常數？ |
| 4. 正常可見 | 發布出去的效果，真的被畫出來了嗎？有沒有「算出來但沒發布」或「發布了但沒畫」？ |

**產出**：每條準則 = 目前的驗證手段（自動化測試／端點／人工）+ 已知未驗項。

### L3 — 端到端觀察（不是讀碼）

**讀碼不算驗證。** 每一項都要實際打後端觀察。

模擬器介面（已盤點，2026-10-21）：
- MCP 工具 **20 個**：`wz_sim_*`（13）、`wz_map_simulate` / `_batch` / `wz_map_patrol_mob` /
  `wz_map_cast` / `wz_map_advise` / `wz_map_ground`（6）、`wz_map_session_*`（3）
- API 端點 **約 50 個**，分三群：
  - `/api/simulate/session/*`（14）— 有狀態
  - `/api/simulate/*` 無狀態（14）— walk/cast/mob/step/trace/probe/advice/geometry
  - `/api/simulate/debug/*`（7）+ look / equip / mob-catalog / mob-info / mob-attacks（10）

**產出**：每個工具與端點 = 「有實測 / 只有讀碼 / 完全未碰」三選一 + 觀察到的輸出。
**「完全未碰」的清單本身就是交付物** —— 它是下一輪的功課表。

### L4 — ADR 合規

對 L1–L3 產出的每一條發現，套 ADR-0005 的判準：

| 分類 | 標準 |
|---|---|
| **缺陷** | 會讓測試者看錯結果（位置錯／因果斷／時間軸錯／看不到） |
| **範圍外** | 只是「遊戲規則比較完整」（冷卻、MP、等級、武器、道具消耗）→ **不修，開工作項目也不開** |
| **顯示正確但讀法不同** | 若會讓顯示錯 → 缺陷；若只是寫法不同且不影響顯示 → 不修 |

## 2. 每份報告的固定格式

1. **改了哪些檔案**（唯讀單應為零）
2. **用了哪些工具、哪裡可能不可靠**
3. **每條結論的證據等級**：`[實測]`（我跑過並貼輸出）/ `[引用]`（開了來源檔貼原文）/ `[推測]`（未驗證）
4. **沒查到的** —— 明說查不到，不要用推測填空白
5. **每條發現都過一遍 ADR-0005 判準**，標明 缺陷 / 範圍外

## 3. 紅線

- **禁止寫入 `C:\MUWORK\GAME\MPSHS`**（可玩客戶端，16 個 `.nx`、3.41 GB）。
- 測試只能用 `C:\mbtest2\` / `C:\mbtest2-gen\`。
- 損壞 fixture 分在**兩個目錄**，不要只查一個。
- 每個 HTTP body 用 `@{ path = $f } | ConvertTo-Json -Compress` 組。
  手寫 `{"path":"C:\..."}` 會拿到看起來像「伺服器拒絕壞檔」的 400，**那是你的測試壞掉**。
- `bin\Release` 被別人的後端鎖住 → 用 `-p:OutDir="$env:TEMP\..."`，**不要殺那個行程**。
