## 一、D 組：憑空機制（先做）

> 判準：**找不到出處的，不是「需要一個好預設值」，是「這個東西不該存在」。**

### D1. `FallMargin = 400`（垂直掉落邊界）

```
客戶端：沒有這個概念。
        MapleCharacter.cs:874-884 找不到地面時 FindBelow 回傳 (99999,99999)，
        Y >= 99996 永不成立 → 永久下墜。客戶端沒有、也沒有終止它。
        唯一的角色邊界是水平的（見 D2）。
我的：  FallMargin = 400，y > bounds.Bottom + 400 就報 fellOut
```

**處置**：刪除垂直邊界，保留水平邊界（D2）。
「掉下去 400px 就判定掉落」是遊戲裡沒有的行為。

**風險**：刪掉後，掉出地圖的行走會走滿 tick 上限。
必須同時讓 D2 的水平邊界與 `ranOutOfGround` 負責終止。
**若刪掉會讓走滿上限的數量上升，這是誠實的結果，不是回歸**——
遊戲裡角色也是一直掉下去。

### D2. 缺地圖邊界夾制

```csharp
// MapleCharacter.cs:777 / :829
if ((X < Map.Left + 20) || ...)  SpeedL = 0;
if ((X > Map.Right - 20) || ...) SpeedR = 0;
```

±20px 的邊界帶，走到就停住。**我的模型完全沒有這個。**

### D3. 不讀 VR 邊界

```csharp
// MapleMap.cs:175-184
Map.Left/Top/Right/Bottom = VRLeft/VRTop/VRBottom/VRRight
// :190-194 沒有 VR 時才用 foothold 極值
```

我的 `ComputeBounds()` 只用 foothold 極值。
對沒有 VR 欄位的地圖兩者相同；**對有 VR 欄位的地圖我的邊界偏窄**。

### D4. `link` 不跟跳

```csharp
// MainForm.cs:758-765
NodePath + "/info/link" 存在 → Map.ID = link 的值，否則用自身 id
```

客戶端**自動跟一跳**。我當 link stub 跳過並回報「沒有 foothold」——
4,532 次 link stub 全是這個原因。

**這是分布裡最大的一塊**。若跟跳正確，其中一部分會變成可走的地圖。

## 四、C 組：怪物剩餘（3 項）

**處置**：改為建構參數可注入，預設保留 20 並在文件寫明預設值的來源限制。
