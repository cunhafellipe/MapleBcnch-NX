# 任務規劃：讓 Agent 能依提示詞用地圖素材生成地圖

**日期**：2026-10-11
**目標使用者**：一文書工Peter
**最終目標**：與 agent 溝通，讓它依提示詞、用現有 WZ/NX 素材生成指定風格的地圖

---

## 為什麼先寫規劃

前兩輪都在做「修好上一輪發現的問題」。這一輪目標不同——
不是修 bug，是**長出新的能力**。這種工作最容易失敗在「做了很多但不知道做到哪」，
所以先把順序、驗收、依據寫下來，做完照著對。

**依據來源**：[MAP-STRUCTURE.md](../docs/MAP-STRUCTURE.md) ——
10 張地圖的實測解剖，不是設計想像。

---

## 核心判斷：先修「工具說謊」

實測發現：`PaletteSets` 給 `ancientForest` 回報了 `thumbPath`，
`thumb` 端點也回 200，但該素材 **9 個條目全是邏輯節點、零視覺 canvas**，
實際放置會 HTTP 400。

```
/palette/entries → 9 筆，全部 w=0 h=0
/palette/preview → {"w":0,"h":0,"missing":true}
/place bsc/0     → 400 does not resolve in the open session
```

**這是最高優先級的原因**：在其餘任何功能之上，若工具回報可用而實際不可用，
agent 產出的每一張地圖都會是壞的，而且**看不出來**（API 回 200）。

> 教訓沿用 JOURNAL/README.md 第一條：專案裡到處是註解宣稱已驗證的行為，
> 其中不少是錯的。這次實測又找到一個。

## 執行順序

### P0 — 讓工具不再說謊（其他一切的前提）

| # | 任務 | 依據 | 驗收 |
|---|---|---|---|
| P0-1 | `PaletteSets` 驗證代表性 canvas 確實有尺寸，標記 `missing` | `ancientForest` 實測 | 對 109 個 set 逐一回報，真空素材被標出 |
| P0-2 | 新增 `validate` 端點：檢查 foothold 鏈完整性、素材真實存在、怪物有 foothold、link stub | 深海峡谷 156 條鏈斷鏈數=0；link stub 3/10 | 對 10 張抽樣地圖跑，結果與人工分析一致 |

### P1 — 讓 agent 能一次表達一件事

實測：20 次 place 只需 **0.17 秒**。**網路不是瓶頸，語意才是。**

| # | 任務 | 依據 | 驗收 |
|---|---|---|---|
| P1-1 | `batch` 端點：一次呼叫多個 op，整批可 undo | 鋪地面需數百次呼叫 | 一次請求放 200 個圖塊，全部落地且 undo 一次全撤 |
| P1-2 | `fillFloor`：鋪地面 + **自動生成 foothold** | foothold layer 跟著視覺圖層走（東部岩山 L0-L3） | 鋪完的地面自带可走鏈，鏈零斷裂 |
| P1-3 | 鏈完整性自動修復 | 零斷裂是硬約束 | 製造斷鏈後能修復並驗證 |

### P2 — 範本驅動與 agent 接入

| # | 任務 | 依據 | 驗收 |
|---|---|---|---|
| P2-1 | 範本機制：從指定地圖提取結構與風格 | 5366 張地圖、1,566 張具名 | 指定地圖編號 → 取得層配置/tile set 組合/尺寸型態 |
| P2-2 | MCP server 包裝底層 API | 使用者要求 HTTP + MCP 雙層 | agent 可透過 MCP 工具完成一次完整生成 |

## 不做的事（以及為什麼）

| 不做 | 原因 |
|---|---|
| UI 改造 | 使用者明確說「先讓 AI 能用，不做 UI」。agent 不看畫面 |
| `Mob.nx`（818 MB）壓測 | 本機當時僅剩 19.6 GB 閒置，存檔峰值已知 14.76 GB。硬測只是把測試機推去 OOM，不能判定程式對錯 |
| 縱向地圖的特殊重力 | 規格已證明 foothold 線段+鏈天然支持 y/x 翻轉，**現有架構已支援**，不需要新程式。留待實測驗證 |
| 中文地圖名搜尋修復 | 已記錄在規格的「未驗證事項」，本輪專注主線 |
| 188 條無用翻譯條目 | 上一輪已記錄，不影響主線 |

## 風險

| 風險 | 緩解 |
|---|---|
| 記憶體不足導致測試失敗 | 實測前先查閒置記憶體；不足就跳過並記錄，不硬測 |
| 「通過測試」但實際不能用 | 每項都要有**真實 API 呼叫 + 冷啟動重讀**才算數 |
| 新端點破壞既有行為 | 每個新端點獨立，不改既有簽章；建置 0 錯誤為底線 |
