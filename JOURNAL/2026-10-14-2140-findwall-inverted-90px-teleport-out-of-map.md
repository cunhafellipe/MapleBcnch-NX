**掉落到地圖外面**。兩個症狀、同一個根因、一個字元。

## 為什麼不是加速度、不是交接、不是 Sin256

依序排除，每一個都量測過：

| 懷疑 | 量測 | 結論 |
|---|---|---|
| `_speed` 沒被夾住 | `:283-284` 有 `Clamp(±MaxWalkSpeed)`，且 frame 回報 `speed=0.000` | 不是 |
| foothold 交接瞬移 | 倒出全部 foothold：58(1710→1800)、84(1800→1890)… **鏈是連續的**，`_x = step.X1` 位移為 0 | 不是 |
| `Sin256` 量級錯 | `Sin256(64) = 1.0`，平地正確 | 不是 |
| `Walk` 之前有別人寫 `_x` | `:296-420` 沒有任何 `_x` 賦值 | 不是 |

**剩下唯一會把 `_speed` 設成 0 並順便改寫 `_x` 的地方，是牆的推擠**
（`:575-587`，`_x = w2.X1 + 1; _speed = 0;`）。

## 直接埋點

```
  afterMove  _x=3190.00 _speed=0.000 atEnd=True fhX2=1800 wall=92@3189
  HANDOVER  fh=58 step=84
```

**`wall=92@3189`** —— 探針在 **x=1716**，回傳的牆在 **x=3189**，相距 1473px。
那是地圖右邊界的牆（`id 92 (3189,-60)->(3189,0)`）。

於是：`_x = 3189 + 1 = 3190` → `atEnd` 成立 → 交接把 `_x` 拉回
`step.X1 = 1800`。**每幀淨 +90。**

## 根因：比較方向寫反了

`Footholds.cs:121-133`，對標的右向查詢：

```csharp
public Foothold FindWallR(Vector2 P)
    foreach (var F in footholds)
        if (F.IsWall() && F.X1 <= P.X && F.Y1 <= P.Y && F.Y2 >= P.Y)
            ...保留，並取 X1 最大者
```

`Footholds.cs:153-171`，左向查詢則是 `F.X1 >= P.X`，取 `X1` 最小者。

**兩個查詢問的是「我剛走進去的牆在哪」** —— 牆在探針**當下或已經越過**的位置，
tie-break 取最近的那一個。這正是呼叫端能寫 `X = WallFH.X1 + 1`
（`CharacterPhysics.cs:578`）的前提：把我放在剛碰到的那道牆的近側。

我的 port 問的是相反的問題 ——「整張地圖上下���一道牆在哪」：

```csharp
// 錯
if (movingRight ? f.X1 < x : f.X1 > x) continue;    // 只留「在前方」
if (best is null || (movingRight ? f.X1 < best.Value.X1 : f.X1 > best.Value.X1))
```

而且**沒有任何距離上限**。於是任何一張有邊界牆的地圖上，
只要角色層的 y 落在牆的跨度內，`FindWall` 就會配到地圖邊界。

修法是把它對齊對標：

```csharp
if (movingRight ? f.X1 > x : f.X1 < x) continue;     // 只留「當下或已越過」
if (best is null || (movingRight ? f.X1 > best.Value.X1 : f.X1 < best.Value.X1))
```

Y 的測試 `f.Y1 <= y && f.Y2 >= y` 本來就對，而且對牆（X1==X2）來說
與對標左向版 `F.Y1 >= P.Y && F.Y2 <= P.Y` 等價，**不需更動**。

## 教訓

- **「從外部量不出來」是有訊號的。** 我從 frame 的 x/y/speed/foothold 推了六輪，
  每一輪的假設都合理、每一輪都被資料推翻。真正終結它的是在函式內部寫
  一行 trace —— 一次建置、四十秒。這已經是第二次了。
- 對標裡的**比較方向**比公式本身更容易被搞錯，而搞錯之後症狀會離根因很遠
  （90px/幀 看起來像「速度失控」，實際是「牆的查詢方向反了」）。
- 移植查詢類函式時要問的是「這個查詢的**語意**是什麼」，不是「這個條件
  在數學上等價嗎」。`X1 <= P.X` 和 `X1 >= P.X` 在各自的查詢裡是對的，
  調換兩者仍然編譯通過、仍然過所有型別檢查，只是整個物理是壞的。
