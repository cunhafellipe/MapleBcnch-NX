# 修正：平地行走每 1.3 秒假爬 4px（worldY 漂移）

時間：2026-10-14 14:09（追加，不覆蓋）

## 現象
角色沿平地走，每約 1.3 秒（每條 foothold 約 69 tick）y 會從 foothold 高度爬升 4px，
然後在交棒時被 `Y = step.Y1` 拉回。視覺上就是「逐漸飄上去再回正」。往左走也會，方向相反。
量測：y 在 180↔184 之間振盪，振幅 4px，`velocityY:0`、`onGround:true`（沒有真的在跳或掉落）。

## 錯誤的根因鏈（我走錯的那條）
先懷疑 foothold 有起伏 -> 量測 95-108 全部 `dy=0`、`y=180`，完全水平，排除。
再懷疑 canvas 旋轉／傾斜 -> 全檔沒有 `ctx.rotate` / `skew`，排除。
再懷疑相機在動 -> `camY` 全程固定 -232.0，排除。
然後我斷言是 `Angle256` 的浮點截尾誤差：水平 foothold 方向應該是 64，
但 `atan2(167,0) * -40.743665431 = -63.999999999175`，`(int)` 截尾成 -63，`+128 = 65`。
`Cos256(65) = -0.0245` 不為零，所以每步 y 偏移 0.025px。

**這個斷言是錯的。** 改掉 `Angle256` 後漂移一模一樣，4px。

## 對照實驗（真正定位的那一步）
與其繼續推斷，不如把那個係數直接歸零，看漂移是不是從這裡來：
`_y -= 0.0f * (float)(Cos256(direction) * _speed);`
重啟、重開檔、重跑 trace -> **振幅 4px -> 0px**。

漂移確定來自 `Walk()` 的垂直分量。但歸零同時證明 Angle256 的方向值本來就不對 ——
我改成 64 之後行為不變，代表執行期算出的本來就不是 64。角度量化在這個實作裡對不上垂直軸。

## 真正的修法
不再用量化後的角度推 y，改成從角色當下所在的線段取真實表面高度：

```csharp
int surfaceX = (int)Math.Round(_x);
_y = fh.SurfaceAt(surfaceX) ?? _y;
```

理由：
1. 垂直軸不再經過角度量化 —— 4px 就是從量化來的。
2. 結構上不可能漂移，因為 y 只是 x 的函數，不是累加值。
