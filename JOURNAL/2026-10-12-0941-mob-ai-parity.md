## 二、刪掉：兩項憑空發明的機制

### 2.1 `Reach = 60` 仇恨判定

```csharp
// 我寫的
Engaged = characterX is { } ex && Math.Abs(ex - _x) <= Reach;   // Reach = 60

// 客戶端 Mob.cs:350-375
switch (Random.Next(200))   // 每幀擲一次
{
    case 50:  MoveDirection = Left;  break;
    case 100: MoveDirection = Right; break;
    case 150: MoveDirection = None;  break;
}
```

**客戶端從不讀 `Game.Player.X` 來決定移動方向。**
整個 `Mob.cs` 唯一與玩家位置有關的分支，是被擊中之後的反應（`:434-460`）。

我的 60px 判定讓每隻怪物都「看得到」角色——而遊戲裡沒有任何機制讓它看到。
`/patrol-mob` 回報的 `engaged` 是在給出一件遊戲裡不存在的事。

**刪掉之後**，`Engaged` 的語意改成：受擊後那一幀的反應（`:434-460`）。

### 2.2 `RespawnFrames = 600` 重生

```csharp
// 客戶端 Mob.cs:443-476
Die = true;                  // 播 die 動畫
// 動畫結束 → SpriteEngine.cs:486-492 → DeadList → Free()
// 沒有計時器，沒有重生。地圖保留這個洞直到重載。
```

我的怪物死後 600 幀復活。**遊戲裡沒有這件事。**

刪掉。`RespawnIn` 保留為恆 0，避免呼叫端編譯失敗，但文件寫明它恆為零的原因。

## 三、修正：三項有實作但值錯

| # | 項目 | 客戶端 | 原本 | 現在 |
|---|---|---|---|---|
| M2 | 擲骰頻率 | 每幀（`Mob.cs:351` 建 `Random`，`:354` 立刻擲） | 每 20 幀 | 每幀 |
| M4 | rx0/rx1 | 僅 Jump(`:586`/`:664`)、Fly(`:723`) | 套用到所有怪物 | 限縮 |
| M8 | 受擊反應 | `:434-460` **反轉 MoveDirection** | 只換貼圖朝向 | 補上反轉 |

M2 的影響比看起來大：怪物以 2px/幀移動，
走完自己身體長度遠少於 20 幀，所以原本是「走一段才轉一次」，
節奏是遊戲裡沒有的。

M4 的關鍵：**Move 型怪物在客戶端完全忽略 rx0/rx1**。
我把地圖的 rx0/rx1 套用到它身上，等於告訴 agent
「這個怪物被限制在此範圍」，而遊戲裡它沿著 foothold 鏈走到頭才轉身。

## 五、過程中的兩個錯誤

### 5.1 連續三次相信了過期的建置

`--artifacts-path .verifybuild` 的建置在程式被鎖住時會「0 錯誤」但**不更新 dll**，
於是我三次修完程式、三次測到舊的行為。

判斷方式：**比對 dll 的時間戳與原始碼的時間戳**。
dll 比原始碼舊，就是沒建進去。

另外 `--artifacts-path` 產出的目錄**沒有 `runtimeconfig.json`**，
執行時會報 `hostpolicy.dll was not found`。
之後一律建置到預設輸出路徑 `MapleBench/bin/Release/net10.0-windows/`。

### 5.2 `Engaged` 在迴圈外讀取

我寫成「跑 60 幀後再看 `Engaged`」，但 `Step()` 結束時會把它清成 false——
所以永遠讀到 false。改成在迴圈內每幀檢查。

這是我第二次犯同一類的錯：**讀一個會被清掉的旗標，而不是讀事件**。

## 七、這一輪學到的

**「補完」和「刪除」是同一件事。**

前一輪我以為對齊客戶端就是把缺的功能補上，
於是 32 項差距裡我只看到「缺」的那一半。

真正危險的是另一半：**我憑空發明的機制會生產假的事實。**
`Reach = 60` 讓 agent 相信怪物會注意到角色，
`Respawn = 600` 讓 agent 相信地圖裡的洞會自己填回去。
這兩件事遊戲裡都不存在，而我的 API 用肯定語氣回報它們。

判準要寫成一句話並記進 commit：

> **每一個數字都要能在客戶端找到出處。
> 找不到出處的，不是「需要一個好預設值」，是「這個東西不該存在」。**
