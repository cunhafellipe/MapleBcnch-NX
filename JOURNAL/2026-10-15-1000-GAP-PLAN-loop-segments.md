### 0.1 三個不能再犯的量測陷阱（全部有實測）

1. **前置幀污染**：在同一個 session 裡先送 `jump` 再送 `up`，量到的 `up` 是殘留的起飛狀態。
   每個案例用**新的 session**。
2. **PowerShell 的 null 陷阱**：`@($null).Count` 是 **1**。`attack-test.ps1` 因此長期回報
   「8 damage entries」而實際上一發都沒中。任何 `@(...)` 的數量都要先確認元素不是 null。
3. **挑選條件比對錯維度**：選「最近的怪」只看 x，會選到頭頂 510px 上方的怪；
   兩個探針因此連續三次報「揮擊壞了」。

## 4. 段 1 — 怪物攻擊執行層（#4）

### 4.1 現況（已量）

資料層 `CombatService.MobAttacks` + `MobAttackSpec.Reaches` 已通，且與存檔逐項一致：

| 怪 | 手動量測 | 伺服器讀到 |
|---|---|---|
| 3300007 | type=0, PADamage=125, conMP=2, after=1200ms, lt=−250,−80 rb=0,0 | 完全相同 |
| 4230101 | type=1, PADamage=135, after=850ms, r=200 | type=1, power=135, after=850 |
| 4220000 | type=2, PADamage=110, after=1320ms, r=160 | type=2, power=110, after=1320 |
| 2400049 | type 缺省, after=1560ms, lt=−275,−175 | type=0, after=1560 |

數量也對：3300007→1、4230101→1、4220000→2、2400049→3、2220000→0。

### 4.2 缺什麼

`MobPatrol.Engage` 還沒用這份清單。要接的是：

| 步驟 | 對標 |
|---|---|
| 由 `reaches()` 建 `available`（先試當前面向，再試翻面） | `MobAttack.cpp:62-78` |
| `first_attack && (距離測試 \|\| !available.empty())` → aggro | `MobAttack.cpp:81` |
| `available` 非空且在地面 → 隨機挑一個、`flip = attack_facing`、`set_stance(STAND)`、`inputx/inputy = 0` | `MobAttack.cpp:88-102` |
| 扣 `conMP` | `MobAttack.cpp:113` |
| 冷卻 `max(duration, delay) + 400` ms | `Mob.cpp:138` |
| 傷害在 `attackAfter` ms 後依攻擊幾何結算 | `MobAttack.cpp:193-217` |
| 播 `attackN` 姿勢（`MobAnimation` 目前只有 stand/move/hit1/die1） | |

### 4.3 量測基線（開工前必跑）

- 全部 2053 隻怪的 `attackN/info` 覆蓋率（目前抽樣兩片 87/206、88/205，約 43%）
- `type` 分布（143 槽：0=76、缺省=20、2=21、1=18、3=8）
- 哪些怪的攻擊 `power = 0`（沒有 `PADamage`，`Mob.cpp:160` 會退回 `watk`，而本專案沒有屬性表）
  —— 實測 2400049 三個攻擊都沒有 `PADamage`

### 4.4 完成定義

- 一隻帶攻擊資料的怪，靠近玩家時**播自己的 attackN 姿勢**（不是 move）
- 傷害在 `attackAfter` 毫秒後才結算，數字取自該攻擊的 `power`
- 沒有攻擊資料的怪（2220000）行為與今天完全相同 —— **這是對照組，不能變**
- 門檻：`chase-verify` / `touch-probe` / `mob-attack-verify` 全綠

## 5. 段 2 — 技能載入角色本身的 img（#2）

### 5.1 現況（部分量測）

`skill-test.ps1` 只驗 4 個技能（1121008 / 10001009 / 空字串 / 梯子上）。
`Skill.nx` 有 76 個群組，前 14 個群組只有 28 張技能圖。
可施放清單端點目前回空 —— **這是量測缺口，還不知道玩家實際能選幾個技能**。

### 5.2 缺口（待細量後填實）

使用者的意思是：技能的圖應該來自**角色自己的 img**（`Character/00002000.img/<skillPose>`），
而不是通用貼圖。這對應 `MapleCharacter.cs:1593-1600`：

```csharp
if (Equip.DataS.ContainsKey(Skill.ID + "/action"))
{
    if (State != Equip.DataS[Skill.ID + "/action"]) ...
    State = Equip.DataS[Skill.ID + "/action"];
}
```

也就是**每個技能在存檔裡自帶一個 `action`，角色姿勢要換成那個**。

### 5.3 開工前必量的三件事

1. `Skill.nx` 總共有幾張技能圖、SkillCastService 現在支援幾個
2. 有多少技能的 info 帶 `action` 節點（決定姿勢是否可解析）
3. 現在玩家能施放的清單從哪來、有沒有上限

### 5.4 完成定義

- 技能清單列出存檔實際有的技能，不是寫死的 4 個
- 每個技能施放時角色播**它自己**的姿勢（可解析時）
- 無法解析姿勢的技能明確降級，不畫錯的姿勢

- `GET /api/simulate/mob-catalog`：2053 列、1662 有名、1543 有圖

### 6.3 圖鑑的完成定義

- 列出存檔實際有的怪，不是前 N 隻

## 7. 段 4 — 地圖載入完整性（#5）

### 7.1 量測結果（重要：**伺服器端是健康的**）

```
幾何：抽 60 張地圖 → 60 張都有 foothold、0 錯誤、0 空
      平均每張 87 條 foothold，60/60 有 portal，60/60 有真實圖層名
美術：抽 40 張地圖 → 927 個圖槽，缺 8 個（0.9%），全部是 l（梯子繩）
      o=492 b=255 t=144 l=36
```

**所以「地圖沒有 100% 載入」不是幾何載入器，也不是美術解碼器的普遍問題。**
剩下的嫌疑只有一個：**瀏覽器端解碼失敗**，而那條路徑（`loadArt` / `loadVisible`
的 `onerror` → `slot.missing`）**沒有任何端點讀得到**。

### 7.2 要做的

1. 加 `missingArtCount` / `missingArtSample` 端點（段 0-b）
2. 拿到真實數字後再判斷：是格式不支援、路徑解析、還是快取
3. **如果數字很小**，就直接回報使用者並結束這一段，不為了湊數字去改東西

### 7.3 完成定義

- 「地圖載入率」是個可查詢的數字，不是印象
- 若真有失敗，失敗的是哪一族圖、哪一個地圖、什麼錯誤

## 9. 本輪我自己被抓到的錯誤（留給後面的段看）

| 假結論 | 真正原因 |
|---|---|
| 「每個姿勢都沒有臉」 | GET `/look` 沒有 slot map；slot 名是 `Face-1` 不是 `Face`；要裸 id 不是路徑 |
| 「攻擊資料全是 0」 | `ReadInt` 沒處理 `WzLongProperty`（NX 的整數型別）。而 `range` 走 `WzVectorProperty` 所以正常 —— **抽查幾何會過，抽查傷害不會** |
| 「普通怪一直打玩家」 | `first-attack-verify` 的前提本身是錯的行為 |
| 「揮擊壞了」三連 | 選怪只看 x，選到不同樓層；再疊加角色走到自己攻擊框後方 |
| 「地圖層順序普遍反了」 | 掃了層頻寬就下結論，忘了問**層內**；真正的 bug 是 `as WzIntProperty` 把 z 讀成 0 |
| C: 磁碟 0 GB free | 建置寫檔瞬間量到，事後自行恢復到 32 GB，未刪任何檔案 |

**共通點**：每一次都是「量測工具有限」而不是「產品錯了」，
而其中兩次讓我一度以為要改產品。段 0 就是為了消掉這個類別。
