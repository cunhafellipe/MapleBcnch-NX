## 開場：兩個數字都不對

委託書給的數字是「缺翻譯的鍵約 107 條」。實測是 **181**。

差在哪裡——`t()` 的鍵是**英文原文**，而絕大多數呼叫是字串串接：

```js
t('Nothing in {archive} matches "{query}". Names come from this client\'s own '
  + 'String archive, so anything it does not name can only be found by id or by path.')
```

`i18n-missing-keys.js` 與 `i18n-coverage.js` 都用 `t\(\s*'([^']*)'` 抓取，**只看得到第一段**。
但執行時 `table[key]` 收到的是**合併後的整句**。於是：

- 字典存的是第一段
- 檢查腳本看的是第一段
- 兩邊同意
- **使用者看到英文**

我把真正的 `i18n.js` 載進 Node 實測，它回傳英文並印出警告。
**101 條字典條目從來沒有被查到過，61 個呼叫點在畫英文**，而覆蓋率檢查把它們報成「已翻譯」。

順帶釐清委託書裡 107 與 118 的分歧：那是**另一個** bug——`i18n-missing-keys.js`
對呼叫點反轉義、`i18n-coverage.js` 沒有，含撇號的鍵因此只在其中一支被報成缺翻譯。
兩支腳本各自在不同方向上錯，`nx-probe/i18n-inventory.js` 是唯一一致的版本。

沒包 `t()` 的字串：實測 **579**（AST 掃描），不是 151。

## 一、i18n 收尾

### 做法

25 個檔案，每檔一個 agent，字典由工具合併而非人工編輯（9 個 agent 同時寫一個檔案，
最後寫的人贏，其餘貢獻無聲蒸發——那比失敗更糟）。

`i18n-merge.js` 會拒絕：不是執行期鍵、無中文、placeholder 漂移、兩個 agent 對同一鍵給不同譯文。
測試在執行期推導 fixture，不寫死鍵名——寫死的那版在該鍵被翻譯後就靜默地測起別的東西了。

### 三個陷阱

**位置參數不是物件屬性。** `emptyState('layers', 'No Mob.wz open', …)`、`toast('…')`、
`el('p', {}, 'literal')` 都是使用者看得見的文字，但搜尋 `text:` / `label:` 永遠找不到。
上一輪就是這樣漏掉 15 條 `emptyState` 標題。

**模組層級的表不能包 `t()`。** 表在 import 那一刻就建好了，包上去會把語言凍結。
正確做法是在使用處翻譯——`ui.js` 的 `SORT_MODES` 一直示範著。

**`Kind` 分類不要翻。** `Image` / `Canvas` / `Property` 來自後端。

### 修掉的三件事

**`{n}` 放進普通字串鍵是可以的，放進 template literal 不行。** 我一開始廣播了錯的規則，
被 MapEdit 實測駁回：`t('Hide layer {n}', {n:3})` 完全正常（字典本來就有這類條目）。
真正無解的是 `` t(`Hide layer ${n}`) ``——原始字串帶的是 `${n}` 兩個字元，字典不可能命中。

**`sections.js` 切換語言後區段名稱停在英文。** 名稱建在 `if (!this.listBuilt)` 裡，
而那個旗標永遠不重設；同一個清單的 tooltip 卻跟著換了。已修，並寫了
`test-section-locale-switch.js` 實跑驗證。

**翻譯完後我自己也犯了一次。** 空狀態提示寫死了 `.wz` 檔名——
但 NX 客戶端**根本沒有 Map002.wz**，只有 `Map.nx`。握著完好 Map.nx 的使用者被叫去開不存在的檔案。
這很可能就是「NX 下編輯器不可用」這個判定的來源。

### 結果

字典 1,206 → **2,321** 條。未翻譯 0、重複鍵 0、placeholder 不符 0。

## 二、NX 地圖編輯器

### 委託的判斷是「不可用」。我實測後認為可以。

```
開檔   → 10 images, 8,404,483 nodes, 35,754 canvases
能力   → available=true, mapCount=5366
開地圖 → 8 layers, bounds, bgm, mapMark, miniMap 5944x1311
編輯   → obj 0 / f: 0 → 42
存檔   → verified: true, differences: [], 9.5 秒
重開檔 → 值 = 42     ← 從磁碟重讀，跨行程
```

`verified: true` 不是唯一證據——值是從**新開啟的封存**讀回來的。

### 四個真實缺陷

**1. `readOnlyReason` 宣告了卻永遠沒賦值**（`MapEditorService.cs:389`）

程式碼自己前後矛盾：`Open` 的摘要說 NX「closed for writing」，同一函式內的註解說
「**It is still editable**」，而 `Save` 真的寫回去並驗證。`RefuseWrite` 這個成員**從未存在過**。

我依實測結果統一了說法。附帶修掉：儲存後的 reload 分支會設唯讀理由，
讓一張**成功存檔**的地圖在整個 session 變唯讀。

**2. 每次 NX 存檔都報假錯誤並清掉復原歷史**

```
historyNote: "pinning the payload under 'miniMap/canvas' failed: Value cannot be null."
```

`NxPngProperty` 覆寫了 `GetBitmap()` 卻沒覆寫 `GetCompressedBytes()`。
但 `NxWriter` 對未修改的 NX 畫布是**直接從映射檔複製位元組**，根本不讀壓縮位元組——
這正是它能 10 秒存完 679 MB 的原因。修法是讓 pin 跳過 NX 畫布並遞迴子節點。

> **我第一版修錯了。** 改成「轉換每個 NX 畫布」，結果解碼了整張地圖的美術，
> **存檔途中直接殺掉行程**。第二版才是對的。記在這裡是因為「修好了」的直覺比「改對了」可靠得多。

**3. `save.seconds` 永遠是 0。** NX 分支從不設定 `Seconds`，UI 就在存檔後顯示它。
10 秒的存檔回報 0。已補時鐘。

**4. 對 NX 使用者說錯話。** 同上，見 i18n 那一節。

### 順帶修掉的工具 bug

`edit-preserving-eol.js` 的 `>>>` 插入模式會**吃掉錨定那一行**——刪掉
`string target = ...` 宣告，下一行卻還在用 `target`。讀起來像離很遠的語法錯誤。
已修，補了兩條回歸測試（14/14）。

## 三、貫穿兩件事的教訓

### 「驗證過」這三個字，要問是誰驗的、用什麼驗的

專案裡到處是註解宣稱已驗證的行為。`NX-TECHNICAL-ROUTE.md` 寫著地圖編輯器
「拒絕 NX」，`Open` 的摘要也說 NX 唯讀——**兩個都錯**，而實際寫回路徑是好的、完整的。
只有把 679 MB 的真檔跑一遍才知道。

同樣地，翻譯那邊的覆蓋率檢查報「已翻譯」，是因為它和字典犯了同一個錯。
**一個檢查若和被檢查的東西共享同一個錯誤前提，它會很可靠地報錯答案。**

### 行尾：這個坑我踩了三次

`.gitattributes` 的註解已經記錄過一次教訓（4,842 行無意義的 churn）。
這一輪：

- `ui.js`：5 行真實修改 → **212 行** diff（Edit 工具把檔案轉成 CRLF）
- `WzSaveService.cs`：8 行真實修改 → **95 行** diff，同一個原因
- **混合行尾的檔案有 11 個，不是委託書說的 2 個**

標準做法是 `git diff --numstat` 與 `--ignore-cr-at-eol --numstat` 必須相等。
委託書說對了，檔案清單說錯了。

### 別讓工具做它不該做的事

我的碎片清除工具用「是某個長鍵的前綴」判斷死條目，誤刪了 `Cash Shop` 和 `Map Editor`——
它們是 `SECTIONS` 的標籤，只是恰好以相同字串開頭。兩者都是**透過變數或表讀取**的鍵，
字面掃描看不到。修正規則後，死碎片數從 116 變成 **0**。
