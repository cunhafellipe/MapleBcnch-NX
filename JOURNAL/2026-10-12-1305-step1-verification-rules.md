## 三、規則抓到一個真 bug：鏈走完了卻還在原地走

### 症狀

```
f1/Map/Map2/260020620.img
  修正前：794 ticks、report「crossed 100% of map」、X 從 1 走到 749
          但全程宣稱站在 foothold 14
  probe：14 只跨 x=0..51；x=300 底下是 27；x=500 底下是 16
  修正後：95 ticks、誠實報 fellOut、X 只到 63
```

### 兩層根因

**第一層：`FindLinked` 只用 id 查找**

```csharp
FootholdPhysics.Foot? byId = null;
foreach (...) {
    byId ??= f;                    // ← 記住第一個同 id 的
    if (Meets(from, f)) return f;  // ← 找到相鄰的才回傳
}
return byId;                       // ← 沒有相鄰就回傳錯的
```

**id 只在 layer/group 內唯一**，客戶端根本不查 id——
`CreateFootholds` 在建鏈時解析連結並存成**物件參考**。
不相鄰的連結在客戶端從來不會成立。

沒有相鄰卻回傳了別層的 foothold，於是角色「交接」到一段很長的線。

**第二層：交接失敗時沒有東西限制 X**

```csharp
if (next is not { IsWall: false } step)
{
    if (!reachedEnd) return;      // ← keep 住舊 foothold，但 X 繼續跑
    ...
}
```

keep 住舊 foothold 不代表停止移動——`_x` 每幀照樣推進。
於是角色沿著一段**早就結束的** foothold 走完整個預算。

客戶端沒有這個狀態：它要嘛接手 `FH.Next`/`FH.Prev`，
要嘛超過 `FallEdge` 轉 `jsFalling`。

## 四、順手補上 `/validate` 的缺口

原本只檢查「id 存在」：

```csharp
if (!ids.Contains(value))
    result.BrokenChains++;
```

**ids 跨層重複，所以「id 存在」證明不了角色踩得上那個幾何。**

新增第 2b 項檢查相鄰性，並用與 walker 相同的 `Touches` 判準——
**驗證器和行走器不能對「什麼叫連結」有不同意見**。

## 六、這一輪真正學到的

### 1. 「量測過的門檻」和「量測過的常數」一樣危險

`ClimbReachX = 40` 有完整的量測理由。
我這次寫的三個門檻（段數、時間、百分比）也都「有依據」。

**它們全部被自己的資料推翻三次。**

唯一的例外是幾何檢查——因為它不猜，它直接問。

### 2. 規則需要被驗證能抓到已知的 bug

我寫完規則的第一件事是跑當前版本，全綠。
**但那不能證明規則有用**，只能證明規則沒誤報。

真正有用的證明是：**故意把 bug 放回去，看它會不會叫。**

我這樣做了兩次，兩次都叫了。

### 3. 誠實報「沒走到」和假裝走到同樣重要

`260020620.img` 修正前報「100% 走完」，
修正後報「95 步後掉落」。

**後者才是對的**——那條鏈走到 foothold 14 就真的沒有下一段了。

一個工具寧可說「我沒走到」，也不該說「我走到了」。
