## A. 可施放技能清單端點

`GET /api/skill-cast/castable` → `{preBb, count, skills:[{skillId,bookId,iconPath,name}]}`

對標的四個條件（`SkillForm.cs:99-106` / `:118-127`）：id 不以 `0` 開頭、有 `hit`、
有碰撞框、有 `effect`。

### 對這個存檔的實測

```
preBb = True     count = 66
with name : 66 / 66
with icon : 66 / 66
1000000（對標已知的排除案例，被動技）listed = False
```

**獨立交叉驗證**：66 筆每一筆都去打 `/api/skill-cast/plan`，確認
`hasCollisionBox && effects>=1 && hitEffects>=1 && id 不以 0 開頭` 全部成立 ——
**66/66 通過，0 違規**。用的是另一個端點，所以這是真正的交叉檢查而不是自我複述。
圖示路徑三筆實抽都能解析（`f8/1000.img/skill/10001009/icon` → `kind=Property`）。

### 這裡踩到一個「乾淨的錯誤答案」

第一版 `PreBB()` 寫成 `<archive>/skill/1000000/level`，漏了技能書那一層，
回傳 **`preBb=false, count=0`** —— HTTP 200、格式正確、數字乾淨。

對標的探針是 `Wz.HasNode("Skill/100.img/skill/1000000/level")`（`SkillForm.cs:85`），
`100.img` 是必要的一層。漏掉它之後**每一個封存都會回 false**，
於是走 non-PreBB 分支去要 `common`，而這個存檔沒有任何技能有 `common` → 全部被濾掉 → 0。

如果沒有交叉驗證那 66 筆，一個 `0` 會看起來像「這個存檔沒有可施放技能」，
然後整個 6.4 會建立在「清單是空的」上面。

## B. 熱鍵綁定端點

```
POST /api/simulate/session/{id}/skills        {"bindings":[{skillId,key},…]}   全量取代
POST /api/simulate/session/{id}/skills/clear
```

按鍵只接受 `A`–`Z`（`SkillForm.Designer.cs:50` 硬寫死 26 個字母）。

七個案例實測，逐條對 `SkillForm.cs:156-174`：

| 輸入 | 結果 | 規則 |
|---|---|---|
| D=1121008, F=12101006 | 兩筆都在 | — |
| 同一技能綁 D 又綁 G | 只剩 G=1121008 | 一技能一鍵，**最後一列勝出** |

## D. 施放與傷害（先做 D 因為它是 A/B 的下游）

`MapSimInput.SkillId` → `CastSkill` → 姿勢 + 傷害。

### ⚠️ 對標的行為：MultiStrike 技能**不造成傷害**

這是這一段最難查、也最該寫下來的地方。`Skill.cs:168-178` 只對三個 id
（`1121008`、`1001005`、`1311012`）設 `MultiStrike = false`，其餘全部 `true`。
從那裡分出的兩半，只有 `false` 那一半接得到傷害：

| | MultiStrike = false | MultiStrike = true |
|---|---|---|
| 建了什麼 | 6 個 `SkillCollision`（`:206-209` `Count=6`）| 每隻怪 6 個 `MobCollision`（`:190-204`）|
| 誰呼叫 `Collision()` | `DoMove` 時間到就呼叫（`:467-473`）| `DoMove` 只呼叫 `Dead()`，**從不呼叫 `Collision()`**（`:462-466`）|
| 傷害處理 | `SkillCollision.OnCollision`（`:478-512`）→ `50000 + Random.Next(700000)`（`:491`）| `MobCollision.OnCollision` 的判斷是 `sprite is SkillCollision`（`Mob.cs:797`），但這條分支裡 `Count=1` 且那唯一的 SkillCollision 不會發動碰撞 |
| 結果 | **有傷害** | **沒有傷害** |

換句話說：`true` 分支的六次碰撞兩邊都沒有人接。`SkillCollision.OnCollision` 的
第一行就是 `if (Skill.MultiStrike) return;`（`:480-481`）。

**照原樣移植，沒有「修正」。** 這是對標的行為，不是移植錯誤，
而且沒有任何測試會因為把它改好而失敗 —— 沒有傷害就是行為。

### 碰撞框照對標算式（`Skill.cs:441-458`）

```
FlipX true (面向右):  Right = X - LT.X + 18 ;  Left  = X - RB.X
FlipX false(面向左):  Left  = X + LT.X        ;  Right = X + RB.X
兩者:                Top = Y + LT.Y ;  Bottom = Y + RB.Y
```

`+18` 是鏡像的一部分，不是補償。框永遠取**最大等級**（`:221-223`），與等級無關。

### 實測

```
1121008 (MultiStrike=false) -> action=skill skillStance='brandish1'
                              damage=1 [2220100=453789]      ← 落在 50000..750000 ✓
10001009(MultiStrike=true)  -> action=skill skillStance='bamboo' damage=0
                              怪 HP 不變 ✓
施放鎖：首發 damage=1，緊接第二發 damage=0（action 仍是 skill）✓
梯子上施放：拒絕（action=climb, skillStance 空）✓
未知 id / 空 id：拒絕（action=stand）✓
姿勢持續：65 / 80 幀（plan totalTime=67）✓
```

### 這個 bug 的樣子：一次 tuple 解構順序錯誤，零錯誤訊息

第一版寫成：

```csharp
var (mobPatrol, kind, mobId, _) = session.Mobs[i];   // ✗
```

實際的順序是 `(patrol, **mobId**, **kind**, extra)`（`Swing()` 裡的解構可以對照）。
後果不是報錯，是：

- `kind == "n"` 永遠不成立（`kind` 其實是 id 字串）
- `_combat.MobFrame(mobId, …)` 收到的是 `"m"`，回 null
- 24 隻怪全部被靜默跳過，傷害永遠 0

而施放的姿勢、動作字、時間軸全都正常，**畫面上看起來像「技能有動但打不到」**。
量測方式是錯的兩次（`@($null).Count` 在 PowerShell 回 1；怪物會巡邏所以拿舊座標比），
最後靠埋點一次定位 —— 埋點已移除（`Select-String TEMP_DIAG` → 0）。

## 測試腳本本身的兩個錯誤（記錄下來，因為它們各自偽造過一次結果）

1. `@($null).Count` 在 PowerShell 是 **1**。任何「有沒有傷害」的計數都會印出 1。
   必須先 `Where-Object {$_}` 再數。
2. **怪物會巡邏。** 用施放「之前」讀到的怪物座標去比施放「之後」的狀態，
   會得到空值並被誤讀成「沒打中」。
