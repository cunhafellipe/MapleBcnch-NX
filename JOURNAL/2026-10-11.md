# 2026-10-11 — NX 素材調色盤：空白的真正原因

起始 commit：`e732c0d` · 分支：`main`

前一輪結論是「NX 地圖編輯器可用」。使用者實際打開畫面後回報：
**素材圖片全部沒顯示，看不出來能不能拉。**

那句回報比我的 API 測試有價值。我驗過開檔、編輯、存檔、重讀——
每一個都通——但我**沒有看過畫面**。而看不見的東西，再怎麼驗證 API 都是可用。

---

## 一、結論先講

素材從來沒有壞。是**索引不到**。

`.wz` 裡 `Tile` / `Obj` / `Back` 是**目錄**；NX 裡是**圖片**，整棵樹少一層。
程式碼到處寫死 `WzDirectories` / `WzImages`，於是 NX 客戶端的整個調色盤是空的。

素材本身完好。我從 NX 取出來看過：

| 來源 | 尺寸 | 內容 |
|---|---|---|
| `f1/Tile/ancientForest.img/bsc/0` | 90×60 | 草皮紋理，像素正確 |
| `f1/Tile/NightMarketTW.img/bsc/0` | 90×60 | 磚牆紋理，像素正確 |

---

## 二、八處同型別的假設

全部是同一個錯誤：**把容器形狀當成固定的**。

| 位置 | 原本的假設 | 後果 |
|---|---|---|
| `MapAssetService.FindLibraries` | 只走 `root.WzDirectories` | 找不到任何素材庫 → 素材組 0 筆 |
| `MapAssetService.Sets` | 只走 `library.Directory.WzImages` | 同上，且下一層同樣是空的 |
| `MapAssetService.Entries` | `is not WzImage` 就拒絕 | 開不了素材內容 |
| `Palette.RepresentativeThumb` | `is not WzImage` 回傳 null | **每張縮圖都是 null** → 格子全空白 |
| `Palette.Entries` | 同上 | 同上 |
| `Palette` 的 npc/mob 圖示 | `root.GetImageByName(...)` | 找不到 sprite 圖示 |
| `Palette` 的 life/reactor 清單 | `foreach (WzImage image in root.WzImages)` | 清單為空 |
| `MapEditorService.FindSetImage` | `WzDirectory library` + `GetImageByName` | **放置一律被拒絕** |

修法是同一個：**改用 `_session.EnumerateChildren` / `WzSessionService.PropertiesOf`**
這兩個型別無關的存取器。地圖開啟路徑本來就靠 `EnumerateChildren` 處理同一個問題——
只是調色盤沒跟上。

### 修了還是不通：中間抓到的兩個自己的錯

**第一個：** 我在 `FindSetImage` 寫 `if (library is not WzImageProperty) continue;`。
但 NX 的 `Tile` 節點是 **WzImage**（`api/children` 回報 `kind: "Image"`），
於是我自己寫的護欄擋掉了唯一正確的節點。放置仍然全被拒絕。

**第二個：** `WzImage` 與 `WzImageProperty` **互不繼承**，共同基底是 `WzObject`。
我先把回傳型別改成 `WzImageProperty` 才發現編譯不過——這是好事，編譯器比我想的可靠。

## 四、還沒解決：放置後存檔會殺掉行程

**這是本輪最重要的未解問題。**

| 情境 | 結果 |
|---|---|
| 未修改的地圖存檔 | 正常，9.5 秒，`verified: true` |
| **放置過圖塊後存檔** | **行程被殺，沒有任何錯誤訊息** |

已排除的：

- **不是記憶體**：系統 63.9 GB 中有 32.6 GB 閒置。
- **不是檔案損壞**：檔案有寫出來，PKG4 標頭正常、節點數 8,400,019 正確。
- **不是例外**：log 裡連一行錯誤都沒有，行程直接消失。
- **不是 NX 寫入本身**：未修改的圖存檔正常。

尚未釐清：是堆疊溢位、是原生interop崩潰、還是 `MapDocument.Build()` 在有放置圖塊時產生
超深遞迴。**下一輪的第一件事就是查這個。**

使用者還沒看到這個修復——他開啟的是舊版。
**在我確認「放置後存檔」不會出事之前，這個修復不該算完成。**

## 五、這一輪的教訓

**「驗證過」和「看過」是兩件事，而我把前者當成了後者。**

前一輪我驗了 API 層的每一個端點，寫下「NX 地圖編輯器可用」，
並在日誌裡記了「沒有視覺確認」。那份記錄是對的——
但我沒有因為它而去看。

使用者的回報（素材沒顯示）比我的 API 測試更接近真相。
**當一個領域裡「所有指標都綠」和使用者說「不能用」衝突時，
指標量的是錯的東西。** 這一次綠燈的指標是「回傳 200」，
而使用者在意的指標是「格子裡有沒有圖」。
