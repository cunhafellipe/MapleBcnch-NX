## 一、開頭：瀏覽器開不起來，其實是自己的問題

前一輪記錄了三種啟動瀏覽器的方式全部失敗（headless、可见視窗、remote-debugging-port），
並推論成「這台機器開不出獨立程序」。

**實際原因只是沒有解掉。** 前一輪只試了 Edge，而這台機器上跑的是 Brave，
profile 被鎖住。可行的做法有兩種，都不必動使用者的瀏覽器：

```bash
# 1. 用真的 Chrome（不是 Brave/Edge），全新的暫存 profile
chrome.exe --headless=new --remote-debugging-port=9333 \
           --user-data-dir=<暫存資料夾> --no-first-run about:blank

# 2. 專案裡本來就有 tools/visual-check/*.mjs，直接用 CDP 說話
CDP_PORT=9333 node tools/visual-check/simulator-view.mjs http://127.0.0.1:5480 out.png
```

`tools/visual-check/` 是前一輪自己寫的，**但從來沒有執行過**。
這是這一輪最該記的事：工具寫好了、README 寫好了、端點通了，
就是沒有跑。寫下工具不等於驗過工具。

## 二、畫面開頭是空的，而且理由是對的

第一張截圖：檔案總覽正常，中文正常，沒有紅字。
`/api/simulate/capabilities` 回：

```json
{"available": false, "mapCount": 0, "note": "No map archive is open."}
```

**模擬器不是壞了，是沒有地圖檔開著。** 開 Map.nx（711 MB）之後：

```json
{"available": true, "mapArchives": ["Map.nx"], "mapCount": 5366}
```

這一點值得單獨講：前一輪說「沒有 WZ 所以驗證無效」是錯的，
但**「沒有開檔所以模擬器是空的」這件事，前一輪從來沒量過**。
它花了 14 個 commit 修後端物理，卻沒有一個動作是確認後端看得到資料。

> 教訓：**先確認輸入存在，再談輸出對不對。**
> 「畫面是空的」有三種原因——程式錯、資料沒開、看錯頁面。這輪三種都排除過了。

## 三、兩個 bug：檢視器一次都沒畫成功

### 1. `g.Footholds is not iterable`

`/api/simulate/geometry` 回的是 **camelCase**：

```json
{"footholds": [...], "ladders": [...], "portals": [...], "bounds": {...}}
```

但 `walkview.js` 讀的是 **C# 屬性名** `g.Footholds`。
`layout()` 第一行就丟例外，畫布停在瀏覽器預設的 300×150 空白。

`Program.cs:95` 全專案設了 `JsonNamingPolicy.CamelCase`——
**所以 API 端是對的，畫面端讀錯了一邊。**
修在 `load()` 邊界正規化一次，不改每一個讀取點。

### 2. 地圖圖片全部沒出現，因為文件根本沒開

`/api/mapedit/doc` 對沒開過的路徑回 **404**（文件不跨重啟/逐出）。
舊碼是：

```javascript
this.doc = docRes.ok ? await docRes.json() : null;   // 404 → null，沒有任何提示
```

`doc` 變 null 之後，**所有 tile 都被靜靜略過**——
走線畫在空白背景上，看起來像「這張地圖沒有圖」。

現在先 `POST /api/mapedit/open` 再取 doc，失敗原因記下來不再吞掉。

## 五、順手確認的兩件事，都不是 bug

**「13 張地圖 0 tick、什麼旗標都沒有」**——實測 `106021005.img`
只有 `info` 一個子節點，本來就沒有 `foothold` 也沒有 `portal`。
回報「No foothold to stand on」是**正確的**。

**驗收腳本全滅**——`acceptance.mjs` 把掛載前綴寫死成 `f1/`，
但那天那個 session 開檔掛成 `f6`。是環境差異不是產品壞掉。
改成從 API 讀前綴，順便在沒有掛載時講清楚原因，而不是印一串 404。

**`save verifies` 失敗**——回 500「file is being used by another process」。
**這台機器同時跑著兩個 MapleBenchX.exe**：6684（服務 :5480）與 29384
（13:39 啟動，早於這一輪的建置）。舊的那個一直抓著 Map.nx，
存檔拿不到獨佔 handle。

關掉兩個行程、只開一個之後：

```
=== D. batch（放置後）===
PASS  save verifies  — 12.56s reopenMs=83 diffs=0
...
29/29 passed
```

**同一支腳本、同一份程式碼，唯一的差別是有沒有第二個行程。**
這個失敗假象差點被我寫成「存檔壞掉」。

> 教訓：**看見 500 先看是誰在擋。** 前一輪「連續三次測到過期的 dll」
> 是同一個病的另一種樣子：正在執行的東西不是你以為的那個。
