## 二、量到的事實

### trace 逐幀

```
stp       x       y    gnd  fh  reachedEnd  below  action
 95    -235     155  True  153      False    153   walk
 96    -237     155 False  153       True       walk   ← 離開鏈
 97    -237     155 False  153       True       fall
...
108    -237     201 False  153       True       fall
```

第 96 步走完 foothold 153 的端點 → 離開鏈，
之後 **224 幀連續下落**，y 從 155 單調下降到 1889，X 凍結在 -237。

### probe 查 x=-237

```
y=202  覆蓋 = [-2604, -2244, -1944, -1644, -1344, -1044, -744, -444, -144, -143]
y=1500 覆蓋 = （完全相同）
FindBelow(落下) = None
```

所有 foothold 表面都在 -143 及以上，全在角色上方。
腳下沒有地面——它**應該**永遠落空。而它確實落空了 224 幀。

**這個行為是對的。錯的是 224 幀之後還能繼續跑。**

## 三、試過的三種修法（都無效）

| # | 做法 | 結果 |
|---|---|---|
| 1 | `airborne` 計數 + 120 幀門檻 | 無效 |
| 2 | `Fall()` 不准重新落在同一個 foothold | 無效 |
| 3 | 加診斷欄位 `AirborneHighWater` | **量到 0**，證明我的推理錯了 |

第 3 項推翻我的推理：角色在空中 224 幀，`airborne` 應該是 224。它是 0。

### 決定性實驗

把門檻從 120 改成 **3**：

```
ticks = 18000, fellOut = false, reason = ""
```

**門檻 3 幀仍然走滿。那段程式碼根本沒有執行。**

我當時排除了四個假設（沒有第二個實作、dll 是舊的、`Fall()` 沒有每幀著地、
`airborne` 沒被重置），全部確認為真——然後就卡住了。

## 四、🔑 真正的解法：去讀源碼，不要讀自己的程式碼

使用者說「為何源碼都給你了，你卻好像找不到方向」——**他說對了。**

源碼早就下載在 `_necrocer_src/`（367 個 .cs），
我卻花五次去讀**自己寫的** `CharacterPhysics.cs`。
那個檔案不會告訴我客戶端怎麼做。

讀了 `MapleCharacter.cs:793-801` 與 `:845-852` 之後，答案一行字：

```csharp
FallEdge = -999999;                  // 預設：永遠不觸發
if (FH.Prev == null)                  // 只有在鏈的末端
    FallEdge = FH.X1 - 10;
if ((FH.Prev != null) && (FH.Prev.IsWall()) && (FH.Prev.Y1 > Y))
    FallEdge = FH.X1;
if ((JumpState == jsNone) && (X < FallEdge))
    JumpState = jsFalling;
```

**`FallEdge` 預設是 -999999，永遠不觸發。**
只有走到鏈末端才設成真正的邊界，而且還要**再往前 10px** 才算離開鏈。

### 我做錯的地方

| 我的做法 | 客戶端做法 |
|---|---|
| `_x >= fh.X2` 就判定離開鏈 | 要**超過**端點 10px 才算 |
| 沒有「前方是牆且牆比角色低」的判斷 | 有，那是牆降的情況 |
| 自己發明 `airborne` 計數器 | **根本沒有這個東西** |

`SpriteEngine.cs:1594` 的 `jsFalling` 只有兩行：

```csharp
Y = Y + VelocityY;
VelocityY = VelocityY + JumpSpeed;
```

沒有計數、沒有上限、沒有任何「掉太久就停」的邏輯。
**那是我憑空發明的，而且它壞掉了。**

### 修正

移除 `airborne` 與 `MaxFallFrames`，改用客戶端的 `FallEdge`。
保留一個位置判斷（掉到地圖底部以下 400px 報掉落），
那是模擬器特有的——客戶端有遊戲結束的處理，不需要。
