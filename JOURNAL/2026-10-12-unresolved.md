# 2026-10-12 — 一個我查不掉的問題，與它教我的事

對象：`610030510.img` 走滿 18,000 幀 · 副本 `MapleBcnch-NX-audit`

**這一輪沒有修好任何東西。** 記錄的是我做了什麼、量到了什麼、
以及為什麼停下來。

---

## 一、症狀

```
POST /api/simulate/character {"path":"f1/Map/Map6/610030510.img","direction":-1}

ticks    = 18000     ← MaxWalkTicks 上限
fellOut  = false
reason   = ""        ← 空：走完沒觸發任何 break
```

地圖寬度 2,068px。以 2.5px/步計算走完需要 **827 步**，
實際跑了 **18,000 步**。

---

## 二、量到的事實

### trace 逐幀

```
stp       x       y    gnd  fh  reachedEnd  below  action
 95    -235     155  True  153      False    153   walk
 96    -237     155 False  153       True       walk   ← 離開鏈
 97    -237     155 False  153       True       fall
 98    -237     156 False  153       True       fall
...
108    -237     201 False  153       True       fall
```

第 96 步走完 foothold 153 的端點 → `reachedEnd=True`、
`groundBelow=''`（腳下沒地面）→ 離開鏈。

之後 **224 幀連續下落**，y 從 155 單調降到 1889，X 凍結在 -237。

### probe 查 x=-237

```
y=202  覆蓋 = [-2604, -2244, -1944, -1644, -1344, -1044, -744, -444, -144, -143]
y=1500 覆蓋 = （完全相同）
FindBelow(落下) = None
FindBelow(站立) = None
```

**所有 foothold 表面都在 -143 及以上，全在角色上方。**
腳下沒有任何地面——它**應該**永遠落空。

而它確實落空了 224 幀。**這個行為是對的。**
錯的是那 224 幀之後怎麼還能繼續跑。

---

## 三、試過的三種修法

| # | 做法 | 結果 |
|---|---|---|
| 1 | `airborne` 計數 + 120 幀門檻 | 無效 |
| 2 | `Fall()` 不准重新落在同一個 foothold（`_lastGroundId`） | 無效 |
| 3 | 加診斷欄位 `AirborneHighWater` | **量到 0** |

第 3 項推翻了我的推理：如果角色在空中 224 幀，
`airborne` 應該是 224。它是 0。

---

## 四、決定性實驗

把門檻從 120 改成 **3**——不可能不觸發的數字：

```
ticks = 18000, fellOut = false, reason = ""
```

**門檻 3 幀仍然走滿。** 那段程式碼沒有執行。

### 排除掉的假設

| 假設 | 排除依據 |
|---|---|
| 有第二個 `WalkCharacter` | `grep` 全檔案，只有一個 |
| 部署的是舊 dll | dll 08:24:26 > 原始碼 08:24:19；含 `fell for ` 字串；行程路徑正確 |
| `Fall()` 每幀重新著地 | probe 證明 x=-237 下方無地面 |
| `airborne` 被其他分支重置 | 診斷欄位實測 0 |

**剩下的矛盾**：程式碼正確、路徑正確、dll 正確，但那段不執行。

## 五、我為什麼停下來

**我讀了五次程式碼，五次都自洽，卻每次都與實測不符。**

第五次之後我意識到：讀程式碼在這個問題上無效。
但我還是又加了診斷欄位、做了一次極限實驗——
那些是有用的（證明推理錯了），但我花了太多輪。

正確的做法是**第一輪就埋點**，而不是第五輪。

計畫已寫在 [PLAN-SIMULATOR-2.md](PLAN-SIMULATOR-2.md) §2：
下一次要埋三個點（`ExitPath`、逐幀 `airborne`、`Step` 前後的 `OnGround`），
先量再修。

### 備案（已在計畫裡）

若診斷後仍無法解釋，用**位置判斷**代替 `airborne`：
X 與 Y 都不動就是卡住——這是觀察，不是推論。

**明確不可接受**：調大門檻讓那張地圖從「空 reason」
變成「假的 fellOut」。那是把錯誤藏起來，不是修好。

## 七、這一輪學到的

**「實測通過」與「我懂了」是兩件事。**

我以為讀完 MapleNecrocer 原始碼就懂了它的機制——
事實上我懂了 13/14 項，而剩下那一項（空中如何判定卡住）
我讀了五次都沒懂。

誠實的差別在於：**說出來**。
前兩輪我會把「2/14」說成「完成」，
這次我說「2/14 加上做不完的那一項，而且我不知道為什麼」。

後者比較有用。
