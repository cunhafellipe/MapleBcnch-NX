版本 1.4.0 而非 1.3.1：這次合併新增了 8 個 `wz_archive_*` 工具，
是新增能力不是修 bug。

**兩個說明章節都保留**，遠端的 asset 章節放前面。

順帶改掉一句會變矛盾的話：合併前寫「Two surfaces over one
MapleBench backend」，合併後是四個面向，已改為「Four surfaces」。

## 八、程式碼審查揪出並修掉的四個缺陷

合併本身是乾淨的（只有一個文字衝突），但**兩個分支各自帶進的缺陷**，
是review 與實測才找出來的。全部已修，全部有實測證據。

### 1. 匯出會刪掉使用者開著���封存的內容 🔴

`/export/node-img` 在目標是 `WzImage` 時寫 `image = existing`，
直接指到 session 裡那個物件。`8cf3780` 為解決 UOL 的 NRE 加的
`DropLinkedCanvases` 會呼叫 `property.Remove()`，那是**就地**從容器移除，
而 `WzImage.RemoveProperty`（WzImage.cs:339）會把 `Changed` 設成 true。

所以只要匯出的圖片裡有一個解析不了的 UOL 或 `_outlink`
（`Skill_00007` 正是這個狀態），復原路徑就會從**開啟中的封存**裡刪掉
那些節點，下次存檔再把殘缺寫回磁碟。巢狀的 `WzSubProperty`
刪除連 dirty 都不會亮。

**修法**：先複製再處理，且復原路徑只動到複本。
實測匯出 20.8 MB 的 `Effect.img`，該 image 的 child 數前後都是 11、名字相同。

### 2. dry run 會關掉使用者開著的封存 🔴

`wz_archive_split` 無條件在 `finally` 關閉 `fileId`。但後端的 `Open`
對已開啟的路徑**會重用同一個 session id**（實測：第二次 open 回傳
同一個 id），所以「拿到的 id」不等於「自己開的」。
而 `finally` 在 `dryRun` 的 `continue` 之後照樣執行。

agent 照著 `Program.cs` 的指示先跑 `dryRun=true` 試算，
使用者未存檔的編輯就沒了，而報告只寫「nothing written」。

**實測對照**（先開好 Map.nx 再跑 dry run）：

```
修正前   BEFORE f5 → AFTER (none)    封存被關掉
修正後   BEFORE f7 → AFTER f7        完好
```

### 3. 匯出遇到重複名稱會整個失敗

逐個 child 複製時只擋 `NullReferenceException` 與 `InvalidCastException`，
但 `WzImage.AddProperty` 遇到重複名稱丟的是 `System.Exception`，會直接
變成 500——正是 `8cf3780` 想消掉的那個。重複名稱在這個 codebase 是
合法情況（`WzPropertyCollection` 有 `DuplicateCount`，`WzPath.Child`
用 `#n` 消歧）。改成讓副本名字加後綴，寧可形狀不同也不可內容遺失。

### 4. split 的回報會高估成果

- `limitFiles` 中斷時只寫「Wrote N .img files」，N 看起來像總數。
  改成明確寫 `PARTIAL RUN ... NOT the complete set`。
- `SafeName` 會去掉檔名系統不接受的字元，兩個不同名字可能收斂成同一個
  檔名（`a/b` 與 `a?b` 都變 `a_b`），後寫的直接蓋掉先寫的，
  報告卻照樣兩筆都算。改成撞名時加 `~2` 綴字。
