# 2026-10-14 — 6.2 攻擊沒有動作：後端查錯了封存檔，不是前端沒接

對應 `HANDOFF-2026-10-14-simulator-parity.md` §6.2，交接寫的是「**後端有、前端沒接**」。

## 交接的描述不準，而且不準得有方向性

原始碼上這條鏈是通的：

| 位置 | 內容 |
|---|---|
| `MapSimSessionStore.cs:577-582` | 擲骰子從武器的組裡選一個姿勢 → `body.SwingPose(stance, 48)` |
| `MapSimSessionStore.cs:1075` | `AttackStance = body.AttackStance` 放進 frame |
| `avatar.js:195-201` | `if (action === 'attack') { const s = tick?.attackStance; if (s) return {state: s, animated: true}; }` |

前端消費端寫得好好的。實測發現 **8 次揮擊 `attackStance` 全是空字串**，
所以問題在伺服器送出來之前就沒了。

## 根因：`AttackStancesFor` 查 `f2`，而武器在 `f1`

```csharp
// 修前：CombatService.cs:233
if (_session.TryResolve(Path("f2", "Weapon", id + ".img")) is { } image ...
```

`f2` 是 Base.nx。實測三個封存的結構：

| 封存 | 頂層內容 |
|---|---|
| `f1` Character.nx | 身體圖 + **`Weapon/`**（1000+ 張，含 `01302000.img`）|
| `f2` Base.nx | `StandardPDD.img`、`smap.img`、`zmap.img` —— **沒有 Weapon** |
| `f7` Item.nx | `Cash`、`Consume`、`Etc`、`Install`、`Pet`、`Special` —— **也沒有 Weapon** |

`f1/Weapon/01302000.img/info` 確實存在，21 個子節點裡就有 `attack`。

**同一個檔案的每一處其他查詢都用正確寫法**，只有這一處硬寫檔號：

```csharp
// AttackBox():82-93  ← 正確示範
foreach (OpenFile file in _session.SelectRoleSources("Character", null))
    foreach (string prefix in new[] { "Afterimage", "Character/Afterimage" })
        string imagePath = Path(file.Id, prefix, image);
```

`SelectRoleSources("Character", null)` 就是「哪幾個開著的封存扮演 Character 角色」。
`MobPatrol` / `MobSpriteService` / `CombatService` 的怪物查詢也都是這個寫法。
改法就是照抄它。

## 為什麼這個 bug 可以活這麼久而且看起來像好的

`/api/simulate/look/attack-stances` 這個端點有兩條路：

```
?attack=1        -> [stabO1,stabO2,swingO1,swingO2,swingO3]   armed=true    ← 靜態表，有值
?weapon=01302000 -> []                                        armed=false  ← 壞的那條
```

端點本身回 **HTTP 200 + 空陣列**，不是錯誤。交接 §6.2 引的就是 `?attack=1`
那條路的輸出（交接寫「裝劍後 `attack=1` 回 [...]」），於是端點看起來完全正常。

而 `Swing()` 走的是 `?weapon=` 那條路。**驗證端點用的參數和實際呼叫端用的參數不同**，
所以端點是健康的、呼叫是壞的。

順帶說明交接裡「但『打到怪物時播哪一個』的接線還沒做」這句：
`Swing()` 在命中迴圈**之前**就擲骰子了（`:577` 在 `:585` 的 for 之前），
所以「有沒有打到」本來就不參與姿勢選擇 —— 那是對標的行為
（`CharLook.cpp:706` 每次攻擊從該武器的組裡隨機取一個，不看命中）。
姿勢不是「打到才播」，是「揮就播，命中與否不影響姿勢」。

## 驗證

校準（每次都先跑，見守則 §7.1）：

```
?attack=1        -> [stabO1,stabO2,swingO1,swingO2,swingO3] armed=true
?weapon=01302000 -> [stabO1,stabO2,swingO1,swingO2,swingO3] armed=true   ← 修前是 []
?attack=0 (bare) -> 0 armed=false
按住右 30 幀      -> x=1783.9783 action=walk speed=2.5      ← 修前修後逐位元相同
```

8 次揮擊（站定後放開→按下，攻擊鍵是邊緣）：

```
swing 0: action=attack attackStance='stabO1'
swing 1: action=attack attackStance='swingO2'
swing 2: action=attack attackStance='swingO1'
swing 3: action=attack attackStance='stabO1'
swing 4: action=attack attackStance='swingO1'
swing 5: action=attack attackStance='stabO1'
swing 6: action=attack attackStance='swingO2'
swing 7: action=attack attackStance='swingO2'
distinct = stabO1, swingO1, swingO2     全部在宣告的組內
damage entries = 8
```

徒手對照組 8/8 空 —— `CharLook.cpp:594` 在索引表之前就 return，
所以無武器**不應該**有姿勢，這個空值是正確的。

## 改動範圍

`Services/Simulate/CombatService.cs` 一個方法（`AttackStancesFor`）：
把硬寫的 `Path("f2", ...)` 換成 `SelectRoleSources("Character", null)` ×
`{ "Weapon", "Character/Weapon" }` 的雙拼寫探測，並補上其他方法都有的
`lock (_session.Gate)`。

`AttackStances(int)` 的靜態表、`AttackBox()`、傷害公式、命中判定一律沒動。

## 一條要記住的方法論

**驗證端點的參數必須和呼叫端用的參數同一條路。**
這次端點是對的、呼叫是錯的，兩者長得一模一樣（都是 200、都是那個名字），
所以「端點測過了」完全不構成「呼叫端對了」的證據。
