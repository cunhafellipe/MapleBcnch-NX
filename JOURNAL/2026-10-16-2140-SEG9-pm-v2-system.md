## 2. 實作（D1–D6 全部完成）

### D1 — 讀不出來的項目變成硬錯誤

`parse_frontmatter_checked()` 回傳錯誤原因，`load_items(strict=True)` 把每個壞檔
標記出來。`check` 與 `doctor` 都用它。

**這一條是被自己的歷史證明需要的**：W-055 就是因為 BOM 讓 `startswith("---\n")`
回 false，解析回空字典，而空字典「通過了每一條規則」。

### D2 — 工作項目 frontmatter v2

新增 `workstream` / `kind` / `risk` / **`verify`**（可執行驗收）：

```yaml
verify:
  - cmd: node MapleBench/tools/sim-skills-check.mjs
    expect: 33 passed, 0 failed
```

`check` 新增：枚舉驗證、`depends` 必須是 DAG（成環即報）、
SPEC 與 runner 交叉驗證。**54 個舊項目只給遷移提示，不報錯**——
一個全紅的檢查會教人忽略它。

### D3 — `pm/SPEC.yaml`：唯一真實來源

16 個 area（含 criticality 與實測路由數）、26 個 suite（檔案、runner、verdict、
**`asserts`**、one-shot、flaky）、3 條 invariant。

`doctor` 交叉驗證 SPEC 與 `gate.ps1` 是否一致——**而且這個檢查第一版就抓到
自己說謊**：它用「gate.ps1 裡有沒有出現這個字串」判斷，結果 `save-audit`
因為出現在「解釋它為什麼不在 gate 裡」的註解中被判成 DRIFT。
**探針量到的是註解。** 改成比對 `Run '<id>'`。

## 4. 過程中抓到並修掉的四個自欺

| # | 現象 | 真相 |
|---|---|---|
| 1 | SPEC 解析出 `areas: 1`（應為 17） | `note: >` 的摺疊區塊把清單截斷 |
| 2 | `doctor` 報 `server NOT reachable: NameError` | `json` 沒 import——**探針自己壞掉卻在講環境** |
| 3 | `doctor` 報 save-audit `DRIFT` | 它量到的是 gate.ps1 裡的**註解** |
| 4 | `pm.py set` 會**刪掉** `verify:` | `render_frontmatter` 丟棄所有 `_list`。修完並實測：`set` 之後 verify 仍在 |

第 4 個最嚴重：它會讓任何一次 `set` 靜默地把一個項目的驗收條件刪掉。
