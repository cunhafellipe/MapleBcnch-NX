## 真正的坑：`this.state` 不能碰

第一版照著旁邊的 `setWeapon` 寫成 `this.state = r.frame ?? this.state`。
**兩個端點都不回 frame。** `SummonResult`（`MapSimSessionStore.cs:757-775`）
只有 `mobId / resolvedId / requested / spawned / rejected / indexes`，
despawn 回的是光禿禿的 `{removed}`（`SimulatorEndpoints.cs:309`）。

那樣寫會把 `undefined` 賦給 `this.state`，而 `paint()` 用 `if (this.state)` 守衛
（`livewalk.js:827`），於是整個畫布變空、角色不見 ——
正是 404 那條路徑花了一整套重連策略才避開的故障。

召喚出來的怪會在**下一幀**出現，因為帶 `mobs` 的是 `stepFrames()`。

## 第二個坑：控制列在 live 模式下根本不存在

`renderControls()` 開頭是：

```js
clear(this.controls);
if (!this.ticks.length) return;      // 原本
```

而 live 模式進場時走的是 `releaseWalk()`（`walkview.js:655-661`）：

```js
releaseWalk() {
  this.stop();
  this.ticks = [];        // ← 清空
  this.frame = 0;
  this.renderControls();  // ← 然後才呼叫 renderControls
  this.draw();
}
```

**安裝 live 身體的那個呼叫，就是清空控制列的那個呼叫**，之後沒有任何東西會重建它。
所以按鈕即使接好也永遠不會出現在畫面上 —— 功能會看起來像沒做。

改成：

```js
const replaying = this.ticks.length > 0;
if (!replaying && !this.live) return;
```

並把**只有 replay 能用**的那一半（播放 / 逐格 / 速度）關在 `if (replaying)` 裡，
因為那五個控制項全都索引 `this.ticks`：清單是空的時候 `seek` 會被夾到
`ticks.length - 1 == -1`，`play` 會對著空東西跑一個 frame 計數器 ——
這正是 `releaseWalk()` 自己註解在講的衝突。

**縮放沒有被關起來**：`setZoom` / `zoomBy` 讀寫的是 `this.zoom`，從不碰 `ticks`，
所以對 live 身體和對 replay 一樣可用。

而交接文件 §2.1 訂了「任何『使用者看到什麼』的斷言只能用桌面截圖驗證」，
DOM 讀取與合成圖都不算。所以我沒有任何截圖，**不宣稱畫面上看得到按鈕**。

已經確定的是：`renderControls()` 現在在 `this.live` 存在時不會早退，
而 `releaseWalk()` 是設定 `view.live` 之後呼叫它的
（`livewalk.js:340` → `walkview.js:657-659`）——
所以那條路徑一定會重新畫出這一列。這是讀碼加呼叫順序推出來的，不是觀察到的。

## 一個已知但沒修的行為

`renderControls()` 每次都 `clear()` 整條列再重建，所以使用者在輸入框裡打的字
會在下一次重繪時消失。live 模式下重繪的觸發點是縮放按鈕和裝備列，
不是每幀，所以實際影響很小；加防護會碰到 `LiveWalk.busy`（`livewalk.js:700`），
那個旗標是給物理迴圈用的，借來會讓一次召喚卡掉一幀。留著。
