# 2026-10-15 — 第 8 項：召喚怪物的選單（2,053 隻，看得見名字）

## 前提（三個都實測過）

1. **怪沒有 `icon` 節點** —— 全庫 2,053 隻，0 隻有。縮圖只能用 `stand/0`。
2. **對標的 `MobForm.cs:107-140` 本來就是 DataGridView 清單**，不是圖示方格牆。
   裝備那種 21 格 `ImageListView` 是 `AvatarForm.cs:107`。
   所以「圖示方格」是**超出對標的呈現方式**（資料來源仍來自封存，已宣告）。
3. **`100100` 這個節點不存在** —— 封存存成 `0100100.img`，
   `/simulate/mob-sprite` 也把它回報成 link。任何「讓使用者輸入 id」的清單都會漏掉它。

## 新端點 `GET /api/simulate/mob-catalog`


**id 取自封存自己的子節點名稱**，不是讓呼叫端猜的數字 ——
理由見前提 3，猜的清單會漏掉 link 出去的 id。

縮圖路徑用 `TryResolve` 驗過才回，沒有 `stand` 的怪回空字串，
前端就只顯示 id 而不是給一個破圖磚。

## 前端 `openMobPicker()`

- 召喚列多一個「瀏覽…」按鈕，開啟後才載入
- 搜尋比對**名稱或 id**
- 一次最多畫 240 個磚：2,053 個 DOM 節點會讓分頁卡死，而搜尋框本來就找得到每一隻
- 縮圖 `loading="lazy"` + `/api/canvas?path=`，沒縮圖的顯示 `—` 與 id
- 選一隻 → 把 id 填進召喚列的欄位（不直接召喚，和選裝備的行為一致）
