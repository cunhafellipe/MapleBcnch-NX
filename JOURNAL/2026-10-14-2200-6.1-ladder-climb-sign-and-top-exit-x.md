## 缺陷 1：`Up` 與 `climb` 的符號相反 —— 主因

`MapSimSessionStore.Advance`：

```csharp
// 修前
int climb = (input.Up ? 1 : (input.Down ? (-1) : 0));
```

而物理端全部假設 `-1 = 上`：

| 位置 | 內容 |
|---|---|
| `CharacterPhysics.cs:1029` | `_y += climb * ClimbSpeedPerStep` |
| `:1036` | `if (_y <= l.Top && climb < 0)` ←「到頂」 |
| `:1123` | `if (_y > l.Bottom && climb > 0)` ←「到底」|
| `:964` | `offY = climb < 0 ? ClimbProbeUp : 0`，`ClimbProbeUp = -3` 註明是往上爬 |
| `:1154` | 「Negative is up」|
| `MapEditorService.Simulate.cs:600` | 「Climb: -1 up, 1 down」|
| `SimulateWalk.cs:953` | 「Climb intent used, 0 for never. **-1 is up.**」|

**對標是仲裁者**（`MapleNecrocer\Client\MapleCharacter.cs`）：

```
:541  if (Keyboard.KeyDown(Input.Up))
:543      OffY = -3;
:550      Y -= 1.5f;          ← Up 讓 y 變小
:568  if (Keyboard.KeyDown(Input.Down) && JumpState == jsNone)
:577      Y += 1.5f;          ← Down 讓 y 變大
```

地圖 y 越小越高（bounds top=−1345、bottom=180），所以 Up 必須是 **負值**。

修前量測（站 foothold 114，x=1936，梯子 y −533..−271，按住 Up）：

```
#0 -265 → #3 -259   action=climb gnd=False     ← 在往下爬
#4 -265             action=fall  gnd=True      ← 掉回原地面
（5 幀一個循環，onLadder = 0/120）
```

修後：

```
#0 -266.5 → #239 -535   action=climb   onLadder = 240/240
                        出界幀數 = 0
```

終點 −535 = 梯頂 −533 之上 2px，就是 `_map.FindBelow(l.X, l.Top - 5)`
撿到 foothold 51（surface −535）的結果。

**符號寫反的來源找到了**：`CharacterPhysics.Step` 的 XML 註解寫著
`<param name="climb">+1 up a ladder, -1 down one</param>` —— 和同一個檔案
下游七處實作相反。store 照著那行註解寫。註解一併改正。

## 缺陷 2：梯頂出口把角色搬到 foothold 的 X1 —— 導致下不來

修好符號後，5 隻梯子有 3 隻「爬得上、下不去」：

```
x=2505  UP  -1075 → -1345 ✓     DOWN  -1345 → -1345  （400 幀不動）
```

原因：`ClimbOn` 的頂端出口有 `_x = a.X1`。梯子 x=2505 頂到的是
foothold 3（2469..2520），所以出口把角色丟到 **2469**，離梯子 36px，
超出對標自己的 ±10 抓取框 → 之後每一幀 `FindLadderForClimb` 都回 null →
落到 `_ladder is not null` 的靜止分支 → `action=climb-top`，按住 Down 完全沒有反應。

對標的頂端出口**從不改 X**：

```
MapleCharacter.cs:557-564
    Below = FootholdTree.Instance.FindBelow(new Vector2(X, Y - 5), ref BelowFH);
    Y = Below.Y;
    FH = BelowFH;
    Z  = FH.Z * 100000 + 60000;
    InLadder = false;
```

X 維持 `:549` 的 `X = LadderRope.X`。刪掉 `_x = a.X1` 後三隻梯子全部下得來。
（`:1084` 的第二個分支本來就寫 `_x = l.X`，第一個分支是唯一不一致的地方。）

「爬得上」本來就正常，所以這個缺陷讀起來像「爬梯沒問題」—— 只有回頭往下爬才會暴露。

## 已知但刻意沒動的

- `_y = a.Y1` 在頂端出口用的是 foothold 左端的高度；斜坡上應該用
  `a.SurfaceAt(l.X)`（旁邊那個分支就是這樣寫的）。這是既有行為、
  不是這次報的缺陷，本次五隻梯子的頂端 foothold 都是平的，量不出差異。
- 梯頂靜止時 `action` 停在 `climb` 而不是 `climb-top`，因為抓梯分支先 return。
  位置正確、姿態合理，不動。
- 梯子 2472 的底端浮在地面上方 38px，站著抓不到（框只往下延伸 12px），
  跳起來才抓得到。這是地圖幾何，不是 bug。

## 方法論

- 這是「同一個符號寫反」的**第三次**（前兩次：攻擊框 `facingLeft ? Mirror : Box`、
  角色素材 `flip: dir < 0`）。前兩次都留了教訓，第三次還是發生了 ——
  差別是這次註解本身就是錯的來源，所以**註解要跟著實作一起驗**。
- 兩次量測工具壞掉都被「校準」擋下來，而校準條件自己也寫錯過一次。
  沒有校準的話，這一輪會拿「Δx=0、0/120 幀在梯上」當成證據，
  然後去改一個沒有壞的地方。
