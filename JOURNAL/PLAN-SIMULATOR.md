## 二、🔴 下一輪第一件事：修 FindBelow

**這比做任何新功能都優先**，因為現在的結果是假的。

實測軌跡：

```
x= 16 y=154 → 站在 foothold 6 (表面 -3019)
x= 88 y=154 → 站在 foothold 8 (表面 -3019)
x=136 y=154 → 站在 foothold 83 (表面  -422)
```

角色在 y=154，卻站在表面 y=-3019 的 foothold 上。

### 為什麼會這樣

`FindBelow(x, y)` 回傳「y 之下最高的表面」。當角色落到 y=154，
而某個 foothold 的表面在 -3019，那個 foothold 永遠在它下方，
於是每一步都被選中，角色橫著走在空中。

### 修的方向

`FindBelow` 需要知道「角色是從上方掉下來，還是在這個高度走」：

- 從上方掉落（`OnGround == false`）→ 應該持續下落到**真正低於腳下最近的那個表面**
- 已在地面行走（`OnGround == true`）→ 只需要找同一個表面附近的 foothold

換句話說，**查詢需要「從哪裡來」的資訊，不只是 x 和 y。**
現在的簽名 `(x, y)` 不足以回答「我該落在哪」。

### 驗收

修完後，角色走過 101000200 時，Y 必須與 `probe` 查到的表面一致，
誤差在一個 step 距離內。**不是「走完了」，是「走在對的地方」**。

## 三、階段 1 剩下的部分（角色物理）

`CharacterPhysics.cs` 已有：速度、重力、落地、牆擋、`Jump()`。
還缺：

| | 說明 |
|---|---|
| 左右跳躍的實際使用 | `Jump()` 有了，但沒有「什麼時候該跳」的邏輯 |
| 斜坡上行／下行的差異 | MapleNecrocer 的 `GetAngle256` + `Sin256`/`Cos256` 沒實作 |
| 掉落出地圖 | 角色掉出邊界時該回報，不是走完 |

斜坡那項要謹慎：MapleNecrocer 用 256 分度的查表算角度，
這是美術座標系的慣例。本專案若直接用浮點斜率，
視覺上可能有細微差異——**先確認有沒有差異再決定要不要照抄**。

## 五、選 B 的話：完整分解

以下是依 MapleNecrocer 的實作與本專案的現況推導，**尚未實作**。

### 階段 1：角色物理（無渲染）

```
FootholdPhysics 擴充
  ├─ FindBelow(x, y)          已有，驗證過
  ├─ 表面法向量                斜坡的行走方向
  └─ 碰撞判定                  角色體型 vs 牆面

CharacterMotion（新增）
  ├─ position, velocity
  ├─ walk / jump / fall
  ├─ 重力常數                  必須查證，不可用猜的
  └─ step(dt) → 新狀態
```

**必須遵守的實測規則**（全部來自 `docs/MAP-STRUCTURE.md` 第 5 節）：

1. **foothold 的 layer 跟著視覺圖層走**，不是固定值
   （東部岩山 `L0=21 L1=70 L2=14 L3=40`）
2. **`prev`/`next` 雙向鏈零斷裂**。實測所有既有地圖斷鏈數都是 0
3. **斜坡是主流**（深海峽谷 142/156 斜坡，東部岩山 81/145）

**驗收**：agent 生成地圖 → 模擬角色走全程 → 報「第 N 個 foothold 走不過去」
→ agent 修 → 重跑。這條閉環是終極目標。

### 階段 2：逐幀迴圈 + 怪物 AI

```
WorldSim（新增）
  ├─ entities[]                角色、怪物、NPC
  ├─ tick(dt)                  固定時間步長
  └─ 事件佇列                  傷害、死亡、生成

MobAI（新增）
  ├─ 巡邏路徑                  怪物是否沿自己的 foothold 移動
  ├─ 仇恨與攻擊範圍
  └─ 刷新與重生
```

**這階段風險最高。** 怪物 AI 的細節必須從真實客戶端觀察，
不能憑空設計。MapleNecrocer 的 `Mob.cs` 可參考，但它的實作是
static 全域架構，需要重新設計。

### 階段 3：視覺呈現

**這階段要小心不要重寫已有的東西。** 本專案已有 2,224 行的
canvas 渲染器，怪物 sprite 也能從 Mob.nx 正確產出路徑。

要做的是**新增**：
- 一個角色 sprite 的繪製（讀 Character.wz）
- 逐幀播放動畫
- 讓既有的怪物繪製接上模擬狀態

**不是**重寫渲染器。

## 六、怎麼驗證才算數
