# 工作日誌 2026-10-13 — 互動模擬器：從「宣稱完成」到「真的存在」

## 摘要

今天的主題不是寫功能，是**發現功能不存在**，然後把它做出來並用可信的方式驗收。

起點是一句批評：「為什麼你都有參考專案源碼卻完成這種殘次品」。批評成立，事實比批評更糟：宣稱完成的東西裡，大部分在乾淨重建的程式碼裡根本不存在。

## 一、幽靈行程

盤點時發現 `SimulatorEndpoints.cs` 與 git HEAD **零差異**（107 行），session 端點從未留在檔案裡。但我當天稍早確實測到 session API 回 `sessionId`、走 73 幀、MCP 握手成功。

原因：

- 舊行程 PID 33652（`dotnet.exe`，佔 **3.1 GB**）還載著當時記憶體裡的 DLL
- DLL 重建後端點消失，**舊行程仍活著**
- 於是所有 HTTP 請求都打到幽靈 DLL 上

**驗證機制本身失效**：唯一能證明程式碼存在的證據（跑得起來）被一個已不存在的行程頂替。這不是缺功能，是比缺功能更糟的東西——它生產假的「驗證通過」。

### 幽靈行程為什麼會留著

背景程序啟動時用了 `persist_on_release=true`，加上我多次 `taskkill /F /IM MapleBenchX.exe`（**抓不到**，因為行程名是 `dotnet.exe`），以及後來為省事直接 `taskkill /F /IM dotnet.exe`（連帶殺掉自己的隔離 Chrome）。

**教訓**：驗收前必須 `netstat` 找 PID 再精準殺，不能憑印象殺行程名。

## 三、CLI 驗收（取代瀏覽器自動化）

### 為什麼放棄 CDP

我先寫了 `live-walk-check.mjs`，用 Chrome DevTools Protocol 驅動瀏覽器。花五輪才拿到可信答案，過程中的失敗**全部與被測物無關**：

1. 分頁選擇器 `div` 抓到整個頁面殼層，點了等於沒點
2. 連到錯誤的 debug port（舊 Chrome 已死）
3. cache 沒關，量到的是編輯前的舊腳本
4. `<select>` 只有 401 個 option（實際 5,366 張圖），載入的是空地圖 `000000000.img`
5. 截圖時序在 session 建立前，畫面顯示「Pick a map」

每一個都是「報告了與事實無關的通過或失敗」。

### CLI 的做法

新增 `tools/probe/sim-walk.mjs`，範式抄既有的 `mcp-flow.mjs`：**不直接打 HTTP，用 agent 的方式驅動**。好處是不渲染，所以不會 stale；截圖不會被誤認為結果。

## 五、真正學到的

### 1. 「有參考專案就照抄」不是建議，是規則

我核對過 `JumpSpeed=0.6f`、`JumpHeight=9.5f`、`MaxFallSpeed=8`——全中，於是我宣稱懂參考專案。然後在它有明確答案的地方（出生點，6 行）自創了一套 26 行的 `LeftmostX()`，而且把 `int.MinValue` 塞進一個會過濾 foothold 的函式。

**驗證過的部分 ≠ 理解的部分。**

### 2. 幽靈行程會生產假的驗證通過

這是今天最貴的一課。舊 DLL 的行程還活著，我以為「端點存在」其實只是「記憶體裡有」。

規則：**建置後必須 `netstat` 找 PID、殺掉、重啟，然後掃路由表**。

### 3. patch 報成功不代表寫進去了

今天的 session 端點就是這樣消失的。之後全部改用 Python 二進位寫入，並且寫完立刻 `grep` 路由表確認。

### 4. CLI/MCP 優於瀏覽器自動化

不是因為 CLI 比較好寫。是因为**瀏覽器會引入大量與被測物無關的失敗模式**，而每一個都會偽裝成測試結果。有 MCP 的情況下寫 CDP 是純粹浪費。

### 5. 有現成實作時，不要寫第二份

我在 `Peek` 裡手寫欄位映射，編譯錯了三次。專案裡本來就有 `Describe(session, frame)`。**第二份映射是第二個可能與第一份不一致的東西。**

## 七、環境坑

| 坑 | 解法 |
|---|---|
| `maple-mcp.exe` 綁系統 dotnet（僅 6/8） | 改跑 `dotnet.exe maple-mcp.dll` |
| 後端位址環境變數 | `WZ_SERVER`（不是 `MAPLE_MCP_BACKEND`） |
| 從 scratch 啟動會 `mapCount: 0` | 需 `POST /api/files/open-many` |
| `acceptance.mjs` 要 TTY | `stdin is not a tty` 時不能跑 |
| `taskkill /IM MapleBenchX.exe` 抓不到 | 行程名是 `dotnet.exe`，用 `netstat` 找 PID |
