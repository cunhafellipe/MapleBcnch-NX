## 1. 規模：這個對標有多大

`Client/` 共 75 檔、17,898 行。加上 `RenderFormDraw.cs`、`MainForm.cs` 等。

| 面向 | MapleNecrocer | MapleBench | 規模比 |
|---|---|---|---|
| 角色物理（模擬結論的地基） | 2,764 | 1,556 | 56% |
| 怪物與 NPC | 2,885 | 397 | 14% |
| 地圖構成 | 2,310 | 1,640 | 71% |
| 技能與效果 | 1,663 | 0 | 0% |
| 渲染引擎 | 3,843 | 2,686 | 70% |
| 介面 / 輸入 / 雜項 | 5,754 | 0 | 0% |

**行數比例不等於完成度。** 兩邊語言（C# vs C#/JS）與架構都不同，
這個數字只說明「要補多少的量級」，不說明「缺了什麼」。

真正的差距要靠逐項核對，那部分由兩個分析產出，本文件在收到後補上。

## 2. 已經確認的四個缺口（全部有實測證據）

### G1 — 角色與軌跡被畫布裁掉（**使用者可見，最優先**）

地圖美術有畫出來，但**角色與走過的路徑看不到**。

```
實測 120000202：canvas 1094×387, distinctColours=1644
截圖確認：木屋床舖美術可見，但看不到角色、看不到連續軌跡
```

原因：`walkview.js` 的 `layout()`（第 241 行起）只把 **foothold 座標**
納入取景，沒有把地圖美術的邊界算進去。角色的頭在裁切線外。

**驗收門檻**：截圖中可見角色圖樣，且軌跡連續可辨。
驗收方式：`tools/visual-check/simulator-view.mjs` + 像素顏色數
（**不是 paintedPct**——背景填滿時空白畫布也是 100%，
見 `2026-10-12-takeover-saw-the-screen.md` §4）。

### G2 — 地圖清單前端只載 2,000 / 5,366

`simulator.js:82` 寫死 `limit=2000`，後端 `total` 是 5,366。
搜尋框只搜得到已載入的 2,000 張，**另外 3,366 張用畫面根本點不到**。

實測後端沒問題：

```
GET /api/simulate/maps?limit=6000  → 回 5,366 張（全部）
GET /api/simulate/maps?q=260020620 → 1 筆，精準命中
```

**這是純前端一行的問題，後端早就做對了。**
驗收門檻：畫面搜尋能找到任一 id（例如 300010400）。

### G3 — 梯子段未完成對齊

日誌自列未完成：`SpeedL`/`SpeedR` 速度累加器、出生點（portal + `PY-2` +
`jsFalling`）。原始碼 `LadderRopes.cs` 只有 49 行，可完整對照。

另外本地 `ClimbReachX = 40` 是刻意放寬（客戶端 ±10）。
日誌自己標了 B2 這一項：「那是因為 foothold 提前結束，
不該用放寬半徑補」——**這個自我批評是對的，本計畫維持客戶端 ±10**。

### G4 — 怪物 AI 對標程度未驗

`MobPatrol.cs` 標註 `Mob.cs:586,664,723`，但**沒有獨立驗證過**
（背景分析在做）。規模比 14%，是最薄的一環。

## 3. 明確不做的事

| 不做 | 理由 |
|---|---|
| 逐幀即時迴圈 | 已查證 `RenderFormDraw.cs:196-201` 是 wall-clock 驅動的即時迴圈。模擬器要的是**確定性離線步進**，兩者是不同需求。照抄迴圈會讓結論不可重現 |
| 重寫渲染器 | 已有 2,224 行 canvas 渲染器，地圖美術這輪已驗證畫得出來 |
| 改 NX 格式或存檔路徑 | 不在目標內，風險最高（涉及資料損毀） |
| 補粒子系統 / 技能 / 介面 | 對「地圖可不可行走」這個結論沒有影響。列入 §1 表中是為了說明規模，不是待辦 |

## 4. 執行順序

排序依**「影響模擬結論的可信度」**，不是依好不好做。

| 階段 | 內容 | 完成定義 |
|---|---|---|
| **P0** | G1 畫布取景 + G2 清單載入 | 角色與軌跡在截圖中可見；畫面搜尋可觸及 5,366 張 |
| **P1** | G3 梯子段對齊 | 每個常數都能指到原始碼行號；驗收無回歸 |
| **P2** | 缺口清單其餘項目（待背景分析回填） | 逐項有實測證據 |

**每一階段結束都要跑 `acceptance.mjs`（乾淨環境 29/29）與
`simulator-view.mjs` 截圖驗收，兩者都過才進下一階段。**

## 5. 這一輪學到的、必須延續的規則

1. **每個常數都要能指到原始碼行號。** 指不到的，預設是憑空發明。
2. **先確認輸入存在，再談輸出對不對。** 「畫面是空的」有三種原因。
3. **驗收要看結果，不能看回傳值。** paintedPct 會說謊，要看不同顏色數。
4. **被鎖住 / 沒開檔 / 重複行程，先確認是誰在擋**，不要寫成程式壞掉。
