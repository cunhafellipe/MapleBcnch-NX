## 二、Mob.cs 讀到的實際機制

| 位置 | 內容 |
|---|---|
| `Mob.cs:149` | `MoveSpeed = (1 + info/speed / 100) * 2`，無 speed 欄位則為 2 |
| `Mob.cs:161-175` | `MoveType` 由怪物的動畫節點決定：無 `move` 則站著不動，有 `jump` 是跳躍型，有 `fly` 是飛行型 |
| `Mob.cs:89` | 生成參數讀自地圖的 `life` 節點：`id` / `x` / `cy` / **`rx0` / `rx1`** |
| `Mob.cs:586,664,723` | `RX0`/`RX1` 是巡邏範圍，走到任一端點就轉向 |
| `Mob.cs:770-824` | `MobCollision` 是個矩形碰撞盒，延遲啟動後與玩家重疊就扣血，HP 歸零播放死亡 |
| `Mob.cs:445` | 背後被打會先轉向攻擊者 |

`rx0`/`rx1` 是**真實地圖資料**，不是想像——實測 `101000200.img`
的 NPC 節點回傳 `patrolLeft=-16, patrolRight=22`。

### 實作

```
MoveSpeed / Facing / 巡邏範圍 / 轉向 / 受擊硬直 / 擊殺 / 重生
```

驗證（101000200.img, seed=7, 600 幀）：
```
patrolLeft=-16  patrolRight=22   ← 真實 life 節點
25 次轉向，19px 內來回
engaged=true, hitsTaken=1, deaths=1
同種子兩次執行結果完全相同
```

**沒實作 HP 數值**：客戶端寫死 2,000,000，一擊 500,000-1,050,000，
也就是四下打死。這個數字不影響「地圖是否健全」，只影響戰鬥演出。

### 兩個只有全量掃描才會發現的問題

**1. 攀爬地圖被判「沒地方站」**

`101020005.img` 有 261 個 foothold，但**左緣 204 個全是垂直牆**，
57 個水平 foothold 都在別處。這是**純攀爬地圖**（10 個梯子）。

原回報「Nothing to stand on」——真實但沒用。
真實遊戲裡角色是從梯子爬上來的。

修正：左緣全是牆時，改從最近的梯子底部出發並說明原因。
實測修正後從 x=-161 的梯子出發，走到 41%。

**2. 「其他 267 次」其實是第四種判定**

角色站在地上但動不了——太陡的階梯或牆。
不是掉落（`fellOut`）、不是鏈盡頭（`chainEndedShort`），
是我沒命名的第四種情況。已命名為 `stuck`。

## 四、我自己的兩個診斷錯誤

**1. 「Nothing to stand on」的回報不可信**

第一版修法只是把訊息改長，行為沒變。
真正的修法（改從梯子出發）是在讀完 MapleNecrocer 的
`Mob.cs:89` 才想到的——**因為那裡才顯示 rx0/rx1 是地圖資料，
而「有些地圖靠梯子」這件事也才在那裡變得具體。**

**2. `airborneHighWater: 0` 揭穿了我的推理**

我加了診斷欄位想證明「角色從未離開地面」，
結果欄位是 0，但 trace 顯示 `onGround` 兩種值交錯。

**我的推理在第 5 次時已經不可靠了，卻仍在繼續推理。**
診斷欄位該在一開始就加。

## 五、未解決：`610030510.img` 跑滿 18,000 步

### 症狀

```
ticks=18000  fellOut=false  reason=（空）
```

18,000 是 `MaxWalkTicks` 上限。走完沒觸發任何 break。

### 量測到的事實

```
X 從 -1 走到 -237 之後凍結
動作分布：walk 97 / fall 203
onGround：True 300 / False 300（每個取樣點兩種值交錯）
X 不同值只有 96 個
```

X 凍結在 -237，`walk` 與 `fall` 交替發生。
`Fall()` 每幀都重新著地在同一個位置，所以 `airborne` 永遠歸零，
我的「120 幀後中止」永遠不會觸發。

### 試過什麼

| 嘗試 | 結果 |
|---|---|
| 加 `airborne` 計數 + 120 幀門檻 | 無效，`airborneHighWater: 0` |
| 阻止 `Fall()` 重新落在同一個 foothold | 無效 |
| 加診斷欄位量測 | 證明我的推理錯了，但沒指出正確修法 |

### 誠實的狀態

**這個地圖我沒修好。** 影響範圍：10,732 次行走中 1 次（0.009%）。
它不會產生錯誤結論（回報空 reason 而非假的成功），
但它浪費 18,000 幀的時間，批次掃描時會拖慢。

**下一輪第一件事就是這個**，而且要用診斷優先：
先加診斷欄位看 `Walk` 裡是哪個分支在 x=-237 反覆觸發，
不要再推理。

## 六、這一輪明確沒做的
